# app/ — feature entry points

Read on demand (grep the work-item ID); app/CLAUDE.md keeps only the frame. A new feature adds its line here, not to CLAUDE.md.
For the files a work item touched and the handler of every key, see the generated map: `python3 -I tools/code_map.py`, then `build-map/`.

- OS-KEYROWDLG, the F-key row under a dialog or a question: `include/o3os/app/key_prompt.h`, `src/key_prompt.cpp` hold one table per modal overlay (the dialog owns the row: `render_scene` paints it through `draw_owner_keys`, the screen under it draws none, `ViewState::overlay_keys()` is the one predicate), per strip question of File / Config / Modules (`draw_question_keys` marks the answer keys, `ask_text` makes the strip text from the same table) and per boot-disk state (`ViewState::disk_keys`, `App::set_disk_keys`); `keys=` of the state line says the live keys. A new dialog or question adds a table there, never an `F1` in a string: `tools/check_keytext.py` (ctest `keytext`) fails on one outside its reviewed allow-list. Tests `tests/key_prompt_test.cpp`, `tests/support/key_row.h`; unit scenario `platform/mk66/tools/hil/qa_keyrowdlg.json`
