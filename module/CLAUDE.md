# module/ — `.tmod` host: loader, image checks, views; `sdk/` is the MIT module ABI

- Owns the module file format checks (`image`), the stepped SD loader, bump arenas (no heap, reset on project change), the restricted draw API with record-then-replay views, and the table of built-in modules. Must not: trust a file (every refusal is tested), link `platform` (the composition root wires the hooks), or include more than `core`, `usb`, `hal`. `sdk/` is MIT (`sdk/LICENSE`) and must stay free of OS headers.
- Entry points:
  - `sdk/o3module.h`: the C ABI (descriptor, `o3m_host` services, draw API, file header); the ABI version history is in its header comment
  - `include/o3os/module/image.h`, `src/image.cpp`: what a `.tmod` may say; `loader.h`: stepped load; `arena.h`; `view.h`: views; `builtin.h`: modules in the image
  - `sdk/README.md`: what is verified and what is not; `docs/guides/{module-sdk,app-modules}.md`
- ABI changes are additive: a new field/flag/host function goes at the end and bumps `O3M_ABI_MINOR`; anything else is a major bump. Capability bits and published values are frozen, never renumbered. Every older-minor module must still load unchanged. The descriptor is sized per declared minor (`O3M_MODULE_SIZE(minor)`: 64 bytes up to 1.7, 80 from 1.8; `Desc32` is the 64, `DescExt32` the 1.8 tail): write a descriptor's `struct_size` with the macro, never `sizeof(o3m_module)`, and read the members past byte 64 only for a module that declares 1.8. Extend the layout test `module_image_test.cpp` ("the SDK's layout is what the format says"), `module_loader_test.cpp`, `module_host_api_test.cpp`; add the entry to the ABI list in `o3module.h`. It is a published ABI: Level C.
- New module: skills `sd-module` and `tmod-perf`; manifest `module.json` -> header with `tools/o3m_gen.py`, packed by `tools/o3m_pack.py`; code under `modules/<name>/`, starting points in `modules/templates/{instrument,effect,app}/`. Effects (kind 2) run as per-track inserts (OS-INSFX, `audio/insert_host.h`; console-bound until S3 to S7 land); the first sample effect is `modules/effects/biquad/` (the pattern to copy: manifest, one source, a host test against a double-precision reference).
- Tests: `tests/module_*_test.cpp` (they fall in `unit_rest`), `tests/app_grammar_test.cpp` (the eleven shipped apps through the whole stack in the simulator, with `tests/support/app_grammar.h`: group `unit_apps`) and ctest `o3m_*`. The apps' shared source (the one grammar, `draw_rows`, `own_set`) is `modules/apps/common/o3m_edit.h`. Scoped: `build-os-host/tests/o3os_tests --source-file='*/module_*_test.cpp'` plus `ctest --test-dir build-os-host -R 'o3m_' --output-on-failure` (`qemu_module_*` run under `tools/ci.sh qemu`). `module/` is unmapped in `tools/ci.sh`'s scope map, so `O3OS_CI_SCOPE=changed` runs everything.
- Host tests do not prove a module works on the Tracker; name the open hardware check (`sdk/README.md` section 10).
- Docs: ADR 0002, ADR 0014 (app host API). QA rows in `docs/qa/catalogue/modules.md` (format in `app/CLAUDE.md`); hardware steps `platform/mk66/tools/hil/{modules,qa_modules}.json`.
