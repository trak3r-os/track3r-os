# ProTracker MOD and Scream Tracker 3 S3M import (OS-MODIMP)

Status: built, host and QEMU tests green, libopenmpt oracle 13,633 comparisons with 0 disagreements · Maintainer request 2026-10-13: add OS-MODIMP (MOD + S3M) · **New Community OS behaviour**: these are importers; no persistent format of ours changes. Context: radar card `tracker-module-import`, `docs/formats/med.md` (the mapping and the report are shared with the OctaMED importer), ADR 0004 (step FX), 0013 (audio engine).
Tags: **Fact** = measured against libopenmpt 0.7.3 (tests/modimp_openmpt_oracle.py) or read in the layout cited · *inference* = reasoning, not measured. Nothing here claims behaviour of a historical Tracker OG release.

## 1. Scope

**In:** ProTracker `.mod` (`M.K.`, `M!K!`, `M&K!`, `N.T.`, `FLT4`, `FLT8`, `1CHN`..`9CHN`, `10CH`..`32CH`) and Scream Tracker 3 `.s3m` into the project model, through the format registry (`mod` and `s3m`, one reader object, `FormatKind::Project`, read only). **Out:** XM and IT (later: envelopes, multi-sample instruments, NNA), Octalyser/`OCTA`/`CD81`/`TDZx` tags, ADPCM-packed S3M samples, AdLib instruments, S3M stereo samples beyond their left channel.

The 15-sample Soundtracker file has no signature and is the one exception (OS-IMPORT-ANY I6, section 2). Detection is otherwise by signature only: S3M `SCRM` at 44 (with `0x1A`, type 16 before it), MOD tag at 1,080. `kSniffBytes` is 1,084 since this slice (a caller that hands over fewer bytes is not offered the two formats by `sniff()`/`identify()`).

## 2. Layouts read

**MOD.** 20-byte title; 31 sample headers of 30 bytes (name 22, length in words, finetune low nibble, volume 0..64, loop start and length in words); song length (1..128), restart byte, 128 order bytes, 4-byte tag; then the patterns (64 rows x channels x 4 bytes: sample = hi nibble of byte 0 + hi nibble of byte 2, period = low nibble of byte 0 + byte 1, effect = low nibble of byte 2, parameter = byte 3), then the 8-bit signed sample data one after another. The pattern count is the highest number of the whole order table + 1; when that does not fit the file (a few tools leave junk behind the song length) the entries the song plays are the count. `FLT8` stores each pattern as two 4-channel blocks (channels 0-3 in block 2q, 4-7 in block 2q+1) and its order list holds the even numbers (OpenMPT: value >> 1). Sample data that runs past the end of the file is trimmed (counted); a loop is cut to lie inside the sample, and a replay length of one word is no loop.

**15-sample Soundtracker (OS-IMPORT-ANY I6, I7; new Community OS behaviour).** The same fields in a 600-byte header: the 20-byte title, 15 sample headers of 30 bytes, the song length at 470, the restart byte and 128 orders at 472, no tag; then the patterns (4 channels, 1,024 bytes each) and the samples. There is nothing to sniff, so `sniff_kind` never claims such a file and no listing guesses it; `Module::open` takes a file with no known tag when `is_soundtracker15` holds: song length 1..128; every order the song plays below 64; every sample volume at most 64; no sample whose loop (more than one word) starts beyond its length, whatever the unit of the start; the title and the sample names printable ASCII or NUL; bytes 470..491 not all printable text with no NUL (that is the 16th sample's name in a 31-sample file with a tag this reader does not know, which stays refused); and the file at least as long as the header, the patterns (the highest order of the whole table + 1, or of the played ones when the table does not fit or holds an order of 64 and up; `open` counts the same way) and every sample but the last, which may be short (trimmed and flagged as in a 31-sample file). `ModuleImport` tries it only when the name says MOD (`.mod`, `mod.`) or says nothing. It reads as a 4-channel `M.K.` module (`Variant::St15`, tag text `ST15`) with 15 samples (the model gets 15 instruments, not 31), effects as ProTracker's, the restart byte ignored (Soundtracker files keep another value there). **Open research question:** Ultimate Soundtracker's own effect numbering (1 arpeggio, 2 pitch bend) and the unit of the sample loop start are not detected or handled; both need a real file to decide. The reader takes the loop start of a 15-sample file in words, as ProTracker's header does; this is unverified (the oldest files may store it in bytes, as other players are said to handle), so a loop in such a file may start at twice the right place until a real file settles it. Tested with a synthetic file built in the test (`modimp_reader_test`, `module_import_test`); no third-party file is in git.

**S3M.** 96-byte header (name, `ordnum`, `insnum`, `patnum`, flags, `cwtv`, sample format 1 signed / 2 unsigned, `SCRM`, global volume, initial speed, initial tempo, master volume with the stereo bit, default-pan flag 252, 32 channel settings), order list, instrument and pattern parapointers (u16, x 16), the optional 32-byte pan table. Instruments are 80 bytes (type 0 empty, 1 PCM, 2.. AdLib; PCM: 24-bit data parapointer, length, loop start/end, volume, pack, flags 1 loop 2 stereo 4 16-bit, C2SPD, name). Patterns are packed: a u16 length (itself included), then rows of entries (channel in bits 0-4, 0x20 note + instrument, 0x40 volume, 0x80 effect + parameter) ended by a 0 byte. Order 255 ends the song, 254 is skipped, a number with no pattern is skipped (counted).

**Limits (reader).** 32 channels; MOD 128 orders and pattern numbers up to 127; S3M 255 orders, instruments, patterns; every offset is checked in 64-bit arithmetic, no read is ever outside the file, nothing recurses or allocates. The S3M decoder keeps one decoded pattern (10 KB) and is capped at 32 MiB of packed bytes decoded over a whole import (a hostile file that switches between big patterns row after row ends in `LimitExceeded`); a real song decodes each pattern a few times (about 3 KB each).

## 3. Flow (what plays in which order)

A bounded simulation (`mod/flow.h`) lists what the song plays as pieces of source patterns, in the structures of the OctaMED flow, with libopenmpt's rules (**Fact**, each pinned by a comparison): rows are applied channel by channel; **break** (MOD `Dxy`, S3M `Cxy`) goes to the next position at row x*10+y (over 63: MOD plays row 0, S3M ignores the command); **jump** (`Bxx`) to position xx, row 0 (MOD: it clears a break row set by a channel to its left, S3M keeps it; a position past the end restarts at 0); **pattern loop** (`E6x`, `SBx`): x=0 marks the start (row 0 until one is set), x>0 plays the body x more times, per channel, counters reset when a position is entered, a loop that jumps back wins over a break or jump on its row; **pattern delay** (`EEx`, `SEx`) replays the row x times with its notes cleared and its commands kept (MOD: the last delay of a row wins, S3M: the first); speed (`Fxx` < 0x20, S3M `Axx` 1..255) and tempo (`Fxx` >= 0x20, S3M `Txx` >= 0x20) as BPM with the tick of 2.5 / BPM seconds; `F00` and `A00` do nothing; S3M initial speed 0 is 6 and an initial tempo below 32 is 32. The end of the order list restarts at 0; returning to a (position, row) entered before is the loop of the song, which the model cannot store (reported). Pieces with a tempo or speed command are keyed by the state they start in. Overflow (more than 128 patterns or 255 order entries, e.g. a loop of 15 repeats in each of 20 patterns) is refused by default with what the UI needs to offer `Structural` (source patterns and order list, flow commands dropped and counted, `D` and `B` as Break Pattern and Order jump) or `Truncate` (the first 255 order entries).

## 4. Mapping into the model

- **Notes (Fact).** MOD: the nearest entry of ProTracker's period table (856 = C-1 .. 113 = B-3); our note byte is index + 49, which is libopenmpt's note number and puts period 428 (the sample at its native Paula rate) on the sampler's unity byte 61. Periods outside the table are snapped to the nearest note and counted. S3M: octave x 12 + semitone + 13 (C-4 = byte 0x40 = 61, the sample at its C2SPD); a semitone above 11 is the next octave's (libopenmpt); bytes that give a note above 128 are dropped and counted; 254 is a note cut.
- **Instruments.** MOD sample *i* is instrument *i* at the Paula rate of period 428 (8,287 Hz PAL, 8,363 Hz NTSC), so the Amiga engine takes it by rate; volume `round(100 v / 64)`, finetune in 12.5-cent steps, loops as 16-bit positions of the sample (flagged when not exact). S3M instruments keep their own rate (C2SPD, 0 means 8,363, clamped to 192,000), 8 or 16 bit, signed or unsigned, a stereo sample its left channel, and are put on the Modern engine (their notes span octaves a Paula channel cannot play). A MOD (`EngineFx::Off`) or an OctaMED song imported for the Modern engine is written MODERN too: left AUTO, its Paula rate would send it to the Amiga engine at the load, which runs none of the tracker FX (46..56 and 58..62; the Channel pan 57 is on every engine) (OS-BUG-MODENGINE). Numbers above 63 have no slot (the cells that name them lose the number, counted). AdLib and packed instruments are refused with a report line. The PCM is not written by the importer: `read_pcm(slot, ...)` gives 16-bit mono and `pcm_rate(slot)` the rate, as for MED.
- **Volume.** MOD `Cxx` and the S3M volume column (0..64) are twice that in the model's 0..127 (64 is 127); above 64 is 64 (MOD) or counted as invalid (S3M column). A bare note keeps the channel's volume (baked into the step when it differs from the instrument's own, as for MED).
- **Time.** The song is in BPM mode, four rows to a beat: a row of `speed` ticks of 2.5 / BPM seconds is 6 BPM / speed rows-BPM of ours; the Tempo FX (BPM/2 with a fine correction) and the Speed FX carry the changes; below 40 or above 800 BPM of rows the model clamps (counted). When a speed command has no free FX column for the fine correction the tempo is up to 0.8 % off (counted).
- **Tracks.** One per channel; more than 16 keep the busiest 16 (cells x plays, lower channel wins a tie), in channel order, with a report line per dropped channel; the time of a dropped channel (speed, tempo) is carried onto a track that has a slot. MOD pans are Paula's L R R L (repeated, hard); S3M uses the channel settings (left 3 of 15 = 20 %, right 12 = 80 %, mono centre) and the pan table, muted channels are muted tracks, AdLib channels and channels marked unused are not imported (counted).
- **Where the commands run.** A MOD plays through the Amiga voice and the MED tick processor like an OctaMED song: its effects are the engine window (FX 128 + the MED command, data verbatim). An S3M writes the OG and core FX (the MED mapper's own table, `med.md` section 4); `ImportOptions::engine_fx = On` sends an S3M's effects to the engine window (for a module whose instruments the user puts on the Amiga engine), `Off` does the opposite for a MOD.

### Effects (class by design; the report counts each source effect seen, approximated and dropped)

**MOD, 31 effects.** Mapped to the MED command of the same meaning (21): `0xy` arpeggio (00), `1xx` `2xx` (01 02), `3xx` (03), `4xy` (14, ProTracker's vibrato depth), `5xy` `6xy` (05 06), `7xy` (07), `9xx` (19), `Axy` (0A), `Cxx` (volume), `Fxx` (speed/tempo), `E0x` (0F F9 / F8), `E1x` `E2x` (11 12), `E5x` (15), `E9x` (1F 0x), `EAx` `EBx` (1A 1B), `ECx` (18), `EDx` (1F x0). Executed by the flow (4): `Bxx` `Dxy` `E6x` `EEx`. **Mapped to Channel pan (FX 57, OS-COREFX CF2 fold):** `8xx` and `E8x` (not ProTracker effects, but libopenmpt and every tracker since FastTracker read them as a pan, 00 left, 80 centre, FF right; `E8x` is x x 17), as 0..100 (round(xx x 100 / 255)), held until the next one; on every engine. The earlier mapping to the Panning FX (31) in the 33 steps of the MED track pan is gone (it ended with its step, in this OS's own model of that FX; docs/specs/OS-COREFX.md). **Dropped and counted (4):** `E3x` glissando, `E4x` `E7x` waveforms, `EFx` invert loop (with `core_fx`, OS-COREFX CF2: `E3x` -> FX 54, `E4x` -> 52 and `E7x` -> 53, the last two approximated).
**S3M, 41 effects.** Mapped (11): `Axx` `Txx`, `Dxy` (0A, fine 1A 1B), `Exx` `Fxx` (02 01, fine 12 11), `Gxx` (03), `Jxy` (00), `Lxy` (05), `Oxx` (19), `SCx` (18), `SDx` (1F). Mapped to Channel pan (57, OS-COREFX CF2 fold): `Xxx` (0..0x80, 0x40 the centre) and `S8x` (x x 17 of 255), exact, held. Approximated (6): `Hxy` `Uxy` (PT-depth vibrato, depth scale differs), `Kxy` (06), `Rxy` (07), `Qxy` (retrigger without the volume change; FX 55 on the Modern engine), `S2x` (finetune); and the extra fine slides `EEx` `FEx` (a quarter of a step) inside `Exx` `Fxx`. Flow (4): `Bxx` `Cxx` `SBx` `SEx`. Mapped on the Modern engine (OS-COREFX CF3): `Mxx` (FX 58, 0..64; above 64 is ignored as libopenmpt does), `Nxy` (59), `Vxx` (60, 0..64), `Wxy` (61), `Yxy` (62); N and W resolve their parameter memory in the importer (each its own class), Y keeps libopenmpt's per-nibble memory in the engine. Dropped (18; those of CF1 and CF2 are tracker FX on the Modern engine): `Ixy` tremor, `Mxx` `Nxy` channel volume, `Pxy` pan slide, `Vxx` `Wxx` global volume, `Yxy` panbrello, `Zxx`, `S0x` `S1x` `S3x`..`S7x` `S9x` `SAx` `SFx`, and any effect byte above Z.
In the OG / core FX mode (the S3M default, a MOD with `engine_fx = Off`) the MED mapper keeps what that FX set has: Glide for `G`, Tempo / Speed, volume column, Micro-move, Roll, Position, Panning, Gate, Micro-tune, the plain slides as Slide up / down (approximated: PAR-079's unit), and, since OS-COREFX CF1 (`ImportOptions::core_fx`, on exactly when the engine window is off), the tracker FX of ADR 0004 amendment 2: `0xy` / `Jxy` -> 46 Arpeggio (`xy` verbatim), `Axy` / `Dxy` -> 47 Volume slide (`xy`, x up else y down), `EAx` `EBx` / `DxF` `DFy` -> 48 Fine volume slide (x up in the high nibble, y down in the low one; on a row with a note whose volume the importer knows it stays baked into the step, which is exact), `E1x` `E2x` / `FFx` `EFx` -> 49 / 50 Fine porta up / down (4 x quarter units of a Paula period unit) and `FEx` `EEx` (extra fine) -> 49 / 50 with x quarter units, now exact instead of approximated. They last their row (the engine ends them with it: no terminator is written); the importer follows the volume through a volume slide (x or y a tick over the speed's other ticks) so that a bare note keeps what the track ended at (OpenMPT measured). Arpeggio and slides of the same cell as a note act on that note. CF2 adds `Pxy` -> 51 Pan slide, `Ixy` -> 56 Tremor, `Qxy` -> 55 Retrigger (the volume code carried), `S1x` -> 54 Glissando, `S3x` `S4x` -> 52 / 53 (approximated), and resolves S3M parameter memory in the importer (D K L share a memory, E F share one, J Q R S P I their own: a zero parameter takes the channel's last non-zero one). What stays dropped: `Mxx` `Nxy`, `Vxx` `Wxx`, `Yxy`, `Zxx`, `S0x` `S5x` `S6x` `S7x` `S9x` `SAx` `SFx`.

### Playback differences that the report names

- **Slides on tick 0.** ProTracker and ST3 run slides, portamento and volume slides on ticks 1.. only; the engine runs them on every tick unless its SoundTracker-slide switch is on (`AmigaVoices::set_slide_tick0`), which is not a project setting. A MOD import in the engine window counts the cells it writes (`tick0_slide_cells`, drop group "slide timing"): those effects run one tick more per row until the switch is wired to the project (open item).
- ST3.00 "fast volume slides" (`flags & 0x40`, `cwtv 0x1300`) are reported, not applied.
- Global volume and master volume of an S3M, a MOD restart position, and the loop of the song are reported, not stored.

## 5. The import report

`ImportReport` = a `med::ImportReport` (tracks used / kept / dropped with cells and notes, cells, notes out of range, volume baked / clamped, tempo and speed FX, timing carried / lost, per-instrument result, flags and frames, FX counts by MED command) plus: per source effect `seen / approx / dropped` (`fx_name(id)`), periods off the table, bad notes, instrument references dropped, invalid volumes, AdLib and unused-channel cells, slide cells, instruments beyond 63, trimmed samples, clamped loops, rates clamped / defaulted, stereo / AdLib / packed counts, the header values (global volume, master volume, restart, skipped and bad orders). `FormatReport::dropped_groups` names thirteen groups (`drop_group_name`): AdLib instruments, packed samples, stereo samples, instruments refused, channels without a track, effects without a counterpart, effects approximated, global volume, slide timing, loop point, flow, periods off the table, restart position. Counts are of cells mapped: a pattern repeated by a pattern delay maps its row again.

## 6. Verification

- `tools/mod_build.py` (an independent writer of both layouts) against `o3mod_tool dump` (ctest `mod_python`, 15 modules: every MOD variant, S3M instrument kinds, markers, pans, 24 channels).
- libopenmpt 0.7.3 (ctest `modimp_openmpt`, loaded with ctypes from the system, skipped without it, failing under `O3_CI=1`): 14,200 comparisons since OS-COREFX CF1 (13,633 before; the decode now also runs for the Modern engine, and the volume a bare note keeps after slides is compared); ctest `corefx_openmpt` plays synthetic modules through the importer, the sequencer and the whole Modern engine and compares the pitch and the level of every tick with libopenmpt (5,993 comparisons, 0 disagreements since CF2: CF1's cases, S3M parameter memory with zero parameters (`J37 J00`, `D04 D00`, E / F fine, `Q23 Q00`, `I23 I00`, `P04 P00`), the retrigger, tremor and pan slide); the earlier count: : every cell of ten MOD variants and an S3M (note, instrument, volume column, effect text as OpenMPT shows it against the FX this document lists), pitch (MOD 36 notes x finetunes, S3M C2SPD x octaves x 8/16 bit x signed/unsigned), loops, rows visited by 31 flow scenarios, durations of 73 timing cases, more than 16 channels, volume persistence. **Where the two differ on purpose** (and so are not compared): loops of 2-4 words at the very start of a MOD sample (libopenmpt ends them, the Amiga and the importer loop them) and loops that start past the end; S3M pattern loops on two channels (libopenmpt ends the song at the second pass); a pattern delay on the row of a break (libopenmpt lands one row later); MOD notes that need a period below 113 with a positive finetune (Paula's limit: the engine clamps, the formula does not); S3M notes above octave 8 (libopenmpt clamps to 120, the importer keeps up to 128).
- `modimp_reader_test` (21 cases) and `modimp_import_test` (31 cases): golden songs worked out by hand, every effect, the flow, tracks, instruments, the three ways to end for lack of room, step-size independence, a file cut at every offset, mutation fuzz, random bytes, the registered strategy. Both also run on QEMU (`qemu_formats_modimp`, `qemu_formats_modimp_import`).

## 7. Open items

- The engine's slide timing switch (section 4) is not a project setting: a MOD's slides run one tick per row too long. Needs a project-level flag (a new chunk: a persistent-format change, maintainer decision) or a per-import engine switch.
- S3M effects on the Modern engine: arpeggio, volume slides, fine volume and fine slides are the tracker FX 46..50 since OS-COREFX CF1, and pan slide, waveforms, glissando, retrigger with volume and tremor are 51..56 since CF2 (`docs/specs/OS-COREFX.md`); channel volume (M, N), global volume (V, W) and panbrello (Y) are 58..62 since CF3 (the S3M header's initial global volume is still only reported as dropped). Known difference from Scream Tracker: its arpeggio plays from the NOTE and forgets a fine slide's period, ours plays from the slid period (ProTracker's rule); an S3M that mixes the two on adjacent rows sounds different. The pan (S3M `Xxx` `S8x`, MOD `8xx` `E8x`) is Channel pan (FX 57), the track's absolute pan 0..100, held; S3M `Xxx` is 0..0x80 as libopenmpt reads it (`XA4`, the surround, is held to the right). The Panning FX (31) ends with its step in this OS's model (the official firmware's behaviour is an open research question).
- `OCTA`/`CD81`, ADPCM and AdLib are refused (the 15-sample Soundtracker file is read since OS-IMPORT-ANY, section 2); XM and IT are the next importers.
- Not yet wired in the app: the file browser's "import" action and the platform's PCM writer for `Importer::read_pcm` (the same open item as the OctaMED importer).
