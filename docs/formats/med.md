# OctaMED / MED (MMD0–MMD3) compatibility specification

Status: accepted 2026-10-11 (maintainer-delegated; decisions in §8); slices M0 to M2 built (OS-008a, OS-008b) · Maintainer request 2026-10-11: "OctaMED compatibility" · Context: ADR 0004 (step FX), 0005 (licence), 0013 (audio engine), OS-004 and `docs/formats/o3-project.md` (model), radar cards `tracker-module-import`, `amiga-playback-mode`, `octamed-keyboard-shortcuts`.
Tags: **Fact** = read in a cited source `[S#]` (section 9) · *estimate* = arithmetic shown, unmeasured · *inference* = my reasoning, not sourced. Every MMD integer is big-endian; `ptr` = u32 byte offset from the start of the file, 0 = absent; offsets are decimal. WebFetch summaries are model-condensed, so the slice that implements a field re-reads the primary source and pins it with a test. Third-party code is not reproduced here.

## 1. Scope and versions

**Where the reader runs (OS-FLASHDIET I3):** the firmware image does not link this reader any more; it runs in the importer module `modules/importers/tracker.tmod` on the card (built from the `formats_tracker` library's sources), and the image keeps only the probe side in `formats` (`src/tracker_sniff.cpp`: the MMD check is in `app/module_import.cpp`, the `drop_group_name` table in `tracker_sniff.cpp`).

**In:** read MMD0–MMD3 files (OctaMED 4 to SoundStudio); map MED commands onto OG FX, new core FX or engine FX (section 4); play them faithfully in the planned Amiga/Paula mode (section 5); optionally write MMD files (section 6). **The OctaMED keyboard layer** is an input-layer feature, not a file feature: it stays in `octamed-keyboard-shortcuts.md`. What this spec gives it: MED instrument numbers 1..63 keep their numbers (section 3.3), MED's decimal-or-hex volume convention (`FLAG_VOLHEX`) and the command names of section 4 for the editor's command entry. **Out:** pre-MMD MED2/3/4 files, `MMDC` (run-length-packed MMD0 pattern cells, libxmp only `[S5]`), OctaMED 8 (2024) files (format not verified), ARexx, notation, MIDI dump data, SoundStudio plugins.

| Id (hex) | Written by (source) | Adds over the previous | Limits |
|---|---|---|---|
| MMD0 (4D4D4430) | MED V2.1 to OctaMED V6 can write it `[S15, snippet]` | base: 3-byte cells (6-bit note, 6-bit instrument, 4-bit command) | 4/8/12/16 tracks, 256 lines, 256-entry play sequence, 63 instruments `[S1]` |
| MMD1 (…31) | OctaMED Professional, V3–V6 `[S2, S15]` | 4-byte cells (7-bit note, 6-bit instrument, 8-bit command), u16 tracks and lines, `BlockInfo` (name, highlight mask, command pages) | editor limit 3,200 lines `[S1]`; SoundStudio 1.03 can write >16 tracks as MMD1 `[S9]` |
| MMD2 (…32) | OctaMED V5–V6 `[S15]` | play sequences + sections, per-track volume and pan tables, pointer-based song struct, mixing fields (channels, echo, stereo separation) | 1–64 tracks `[S1, S9]` |
| MMD3 (…33) | SoundStudio (V7) `[S1]` | same layout as MMD2; "signals mixing mode"; sounds two octaves lower: OpenMPT shifts the pattern by −24 `[S9]`, libxmp shifts the sample map by −24 `[S4]` | as MMD2 |

**Fact:** the layout document is Teijo Kinnunen's "MED/OctaMED MMD0/MMD1/MMD2/MMD3 file formats", Revision 6, 1996-02-01 `[S1]`; the MMD0/MMD1-only Revision 1 is dated April 1992 `[S2]`. libxmp guesses the writing tool from the `InstrExt` entry size (`>18` SoundStudio 2, MMD3 SoundStudio 1, `>10` SoundStudio 1, `>8` OctaMED 5.02, `>4` OctaMED 5.00, MMD2 5.00, song name or MMD1 3.00, …) `[S4]`.

### 2.3 Blocks, command pages, play sequences `[S1, S9]`
- **MMD0 block:** u8 numtracks, u8 lines−1, then `tracks × lines` 3-byte cells, **line-major** (all tracks of line 0, then line 1…). Cell `xynnnnnn iiiicccc dddddddd`: note 0–63 (1 = C-1, 0 = none), instrument = `iiii` + `x` as bit 4 + `y` as bit 5, command `cccc`, data. libxmp reads it exactly so `[S5]`.
- **MMD1+ block:** u16 numtracks, u16 lines−1, ptr info (may be 0), then 4-byte cells `xnnnnnnn xxiiiiii cccccccc dddddddd`: note 0–127, instrument 0–63, command 0–255, data; the `x` bits must be zero and are masked on read.
- **BlockInfo (36 bytes):** 0 hlmask `ptr` · 4 blockname `ptr` · 8 u32 blocknamelen (with terminator) · 12 pagetable `ptr` · 16 20 bytes "reserved, must be zero" in Rev 6. **Inference from OpenMPT `[S9]`:** SoundStudio uses offset 16 as `cmdExtTableOffset`, an extra data byte per cell for commands 20 and 29 (also read as "7-bit volume present"); the layout of that table is described only by OpenMPT's reader and must be verified on a real file (open question O1).
- **BlockCmdPageTable:** u16 num_pages (extra pages, **excluding** the default page), u16 reserved, then `num_pages` page `ptr`s; each page is a table of `numtracks × lines` cells of two bytes (command, data), line-major `[S1]`. OpenMPT merges extra pages into the cell, spilling to the next row when two commands do not fit `[S9]`; libxmp does not read them (its source has a FIXME) `[S6]`. Whether OctaMED 4/5 can create pages is unclear in forum threads; V6 and SoundStudio can `[S12]`.
- **PlaySeq (MMD2+):** char name[32], u32 reserved (OpenMPT: `commandTableOffset`), u32 reserved, u16 length, u16 seq[length] (block numbers ≤ 0x7FFF). **Inference from OpenMPT:** the command table holds 4-byte entries {u16 position, u8 command (1 stop, 2 jump), u8 extra size} `[S9]`.

### 2.4 Instruments `[S1, S9]`
- `smplarr[i]` → `InstrHdr`: u32 length (**excludes** these 6 bytes), i16 type, then the data. Type: −2 hybrid, −1 synthetic, 0 one-octave sample, 1 IFF5OCT, 2 IFF3OCT, 3 IFF2OCT, 4 IFF4OCT, 5 IFF6OCT, 6 IFF7OCT, 7 EXTSAMPLE (V5+, two extra-low octaves). Low nibble = type (OpenMPT `TYPEMASK` 0x0F); flags 0x10 16-bit (length still in bytes), 0x20 stereo (non-interleaved, length = one channel), 0x18 obsolete Aura type = 16-bit + output device Aura. OpenMPT also knows 0x40 delta and 0x80 packed samples (14-byte packed header) and types −3, −4 (HighLife, VSTi): **not in Rev 6, unsupported in v1, reported.**
- **Sample data:** signed 8-bit, or big-endian signed 16-bit with 0x10. Multi-octave types hold N octaves back to back, shortest (highest pitch) first, each twice the previous: base length = total / (2^N − 1), loop values double per octave; N = 5, 3, 2, 4, 6, 7 for types 1..6 `[S4]`. The note-to-octave tables are `iffoct_insmap` / `iffoct_xpomap` in libxmp `[S4]` and `OctSampleMap` / `OctTransposeMap` in OpenMPT `[S9]`; port from either with notice, do not retype.
- **Synth / hybrid** (`SynthInstr`, 534 bytes, offsets derived in `[S1]`): 0 u32 length (of this struct), 4 i16 type, 6 u8 defaultdecay, 10 u16 rep, 12 u16 replen (hybrid only), 14 u16 voltbllen, 16 u16 wftbllen, 18 u8 volspeed, 19 u8 wfspeed, 20 u16 wforms (≤ 64; 0xFFFF = none), 22 voltbl[128], 150 wftbl[128], 278 u32 wf[64] (offsets relative to the **instrument start**). Waveform: u16 length in words, signed bytes. Hybrid = same, `wf[0]` is a full sample with its own header. Table opcodes ≥ 0x80: volume table F0 SPD, F1 WAI, F2 CHD, F3 CHU, F4 EN1, F5 EN2, F6 EST, FA JWS, FB HLT, FE JMP, FF END; waveform table F0 SPD, F1 WAI, F2 CHD, F3 CHU, F4 VBD, F5 VBS, F6 RES, F7 VWF, FA JVS, FB HLT, FC ARP, FD ARE, FE JMP, FF END. Rev 6 gives names only; behaviour is in libxmp `med_extras.c` `[S7]` (known gaps: vibrato waveform always sine, EST unhandled).

### 2.5 Expansion `MMD0exp` and friends `[S1, S9]`
Offsets (derived): 0 nextmod · 4 exp_smp · 8 u16 s_ext_entries · 10 u16 s_ext_entrsz · 12 annotxt · 16 annolen · 20 iinfo · 24 u16 i_ext_entries · 26 u16 i_ext_entrsz · 28 jumpmask · 32 rgbtable · 36 channelsplit[4] (00000000 = 4/8 channels, 000000FF 7, 0000FFFF 6, 00FFFFFF 5) · 40 n_info · 44 songname · 48 songnamelen · 52 dumps · 56 mmdinfo · 60 mmdrexx · 64 mmdcmd3x · 68 reserved[3] · 80 tag_end. **Conflict:** OpenMPT's struct is 80 bytes with `trackInfo` at 68, `effectInfo` at 72 and `tagEnd` at 76 (inside Rev 6's reserved area, SoundStudio 2 track names and effect groups). There is no size field: read the prefix that lies inside the file, treat the rest as 0.
`InstrExt` (entry size = `s_ext_entrsz`, never assume 18): 0 hold · 1 decay · 2 suppress_midi_off · 3 i8 finetune (−8..7) · 4 default_pitch (0 = none, 1 = C-1) · 5 flags (01 loop, 02 ext preset, 04 disabled, 08 ping-pong) · 6 u16 long_midi_preset · 8 output_device · 9 reserved · 10 u32 long_repeat · 14 u32 long_replen (V7); OpenMPT adds 18 volume, 19 output port, 20 u16 midi bank `[S9]`. `MMDInstrInfo`: 40-byte instrument name per entry. `MMDInfo`: {next, u16 reserved, u16 type (1 = ASCII), u32 length, text}.

### 2.6 Hostile-input rules
A pure validator with typed errors (`Truncated`, `BadMagic`, `BadPointer`, `LimitExceeded`, `Malformed`, `Unsupported`) and the byte offset of the first problem; integers decoded by hand (no struct punning); caps in one `constexpr` table; random access through a `read_at(offset, dst, n)` + `size()` interface (the file is a pointer graph; the forward-only `ByteSource` of the native reader does not fit).
1. **Pointers:** non-zero only where allowed; `52 ≤ p`; `p + size ≤ file_size` in 64-bit arithmetic; a table of `n` entries needs `4n` bytes inside the file. Alignment is not enforced (Rev 6 asks writers for even offsets).
2. **Chains and cycles:** `nextmod` songs ≤ 256 with strictly increasing offsets (OpenMPT's rule `[S9]`); `MMDInfo.next` ≤ 8 hops; ARexx and tag lists are never followed except `MMDTag` until `tag_end` ≤ 64 entries; no recursion anywhere.
3. **Counts:** numblocks ≤ 255 (MMD0/1: the play sequence is 8-bit; libxmp refuses more `[S5]`), ≤ 0x7FFF for MMD2+ but only blocks referenced by the song are parsed; numsamples ≤ 63; songlen ≤ 256 (MMD0/1); tracks 1..64; lines+1 ≤ 9,999 (libxmp's SoundStudio limit `[S6]`; OctaMED's own is 3,200); pages ≤ 16; synth tables ≤ 128, waveforms ≤ 64.
4. **Physical size:** a block's `tracks × lines × cell size` (and per page `×2`) must fit in the bytes after its pointer; otherwise `Truncated`. Cells are read one line at a time (64 tracks × 4 B = 256 B), so memory does not depend on the claimed counts.
5. **Entry strides:** `s_ext_entrsz`, `i_ext_entrsz` are strides; a field is read only if `stride ≥ offset + size`; `entries × stride` is checked in 64-bit; a skip is never negative (libxmp computes `entrsz − 40` unguarded `[S5, S6]`); entries above 63 are ignored (MMD3 can announce more).
6. **Samples:** `length` is u32: check against the file and against the sample-arena budget (OS-005: 11.19 MiB); stereo needs `2 × length`; an octave split needs `length ≥ 2^N − 1`; loops are clamped into the sample (`rep + replen ≤ length`, replen ≤ 1 = no loop); an oversize sample is refused with its instrument number in the report, never truncated silently.
7. **Strings and names:** copy ≤ the field length, replace bytes < 0x20 and ≥ 0x7F by `?`, truncate to our limits (instrument 32, project 32). Sample file names are **generated** (`i01.wav`), never taken from the file, so no path traversal exists.
8. **Numbers:** tempo 0, speed 0 and lines-per-beat arithmetic cannot divide by zero; every result is clamped to its consumer's range (3.5) and counted in the report (3.6).
9. **Tests:** truncation at every offset of a small synthetic file per version; deterministic mutation fuzz under ASan/UBSan (as `native_fuzz_test`); explicit vectors: pointer 0xFFFFFFFF, `nextmod` cycle, `lines = 0xFFFF` with `tracks = 0xFFFF`, `entrsz` 0..3, `wforms = 0xFFFF`, octave count vs. tiny length, play-sequence entry ≥ numblocks.

## 3. Mapping to our model (`o3-project.md`)
Our model: 16 track slots (12 active by default), 128 patterns of 1..128 steps per track, order ≤ 255, 64 instruments, step = note, instrument, volume (0..127, 255 = unset), 2 FX; native tempo BPM×100 (40..800).

### 3.1 Tracks (MED up to 64 → 16 slots)
1. Count the tracks that carry any note or command in a block **used by the song**; empty tracks never take a slot.
2. If ≤ 16: MED track *k* → slot *k*, in order; `active tracks` = highest used slot, at least 4.
3. If > 16: keep the 16 tracks with the highest played-cell count (cells × times the block is played), preserving MED order; every dropped track is listed (index, cells, notes) in the report. **Default, never silent.** The UI may let the maintainer pick the 16 (data: the same report). Folding two MED tracks into one slot is **not** offered by default: it changes voice allocation and drops the second voice's note-offs (*inference*); it is a desktop "mix-down" option at best.
4. Track type Audio; `trkvol` / `trackvols` (0–64) → slot volume `round(v × 100 / 64)`; `trackpans` (−16..16) → slot pan `50 + round(p × 50 / 16)`; without them hardware panning L R R L (L R R L L R R L for 8 channels) `[S5]`. MMD3 `voladj`, `mastervol` (64 ↔ our default 86, *inference*), echo and stereo separation are reported, not mapped in v1.

### 3.2 Blocks, lines and flow
- **Split:** a block of `L` lines becomes `ceil(L / C)` consecutive patterns, `C` = largest multiple of the beat length (lines per beat from `flags2`, 4 if BPM mode is off) that is ≤ 128, so beats are not cut. Worst case: 3,200 lines → 25 patterns = 25 × 14,384 B = 359,600 B of the 1.84 MiB pool. All tracks of a piece get the same length (our per-track length is used only for the last piece).
- **Linearisation (default, exact for flow):** a bounded simulation walks the song once and emits segments (block, first line, last line): `0F00` and `1D xx` break to the next order entry (line 0 or xx), `0B xx` jumps to order position xx, `16` loops inside a block (00 marks the start, *n* repeats, capped at 15 by libxmp and OpenMPT `[S4, S9]`), `1E xx` repeats a line (the repeated copies keep commands, notes cleared), `0FFE` ends the song, and play-sequence stop/jump entries (MMD2+). Each distinct (block, first, last, piece) is one pattern; repeats are order entries. Visits are capped at 65,536 lines (*estimate*: 128 patterns × 128 lines = 16,384, four times that); a revisit of the same (position, line, loop state) marks the song loop point, which the model cannot store yet (report; OS-004 gap).
- **Structural fallback** when linearisation needs more than 128 patterns or 255 order entries: patterns = blocks, order = play sequence, `0F00` / `1D` → OG Break Pattern 13 (target line dropped), `0B`, `16`, `1E` dropped and counted. The default is to **refuse** (OS-004: "limit exceeded", never silent trimming) and offer the fallback or "first N order entries" explicitly.
- MMD2+: sections are concatenated in section order, each section's play sequence in turn (libxmp plays only the first play sequence `[S6]`, OpenMPT appends sequences `[S9]`). Extra songs (`extra_songs`): import the first, list the others.

### 3.3 Instruments (63 → our 64 slots)
MED instrument *i* (1..63) → our instrument *i* (slot *i*−1), so pattern bytes and the keyboard layer keep their numbers; slot 64 stays free. Per type:
| MED | Ours | Notes |
|---|---|---|
| sample, type 0 | Sample instrument, WAV `samples/instrNN.wav` (this OS's name for the slot; 8-bit data ×256 to 16-bit, 16-bit as it is, stereo mixed down) at the **native** rate, no resampling: 8,287 Hz PAL, 8,363 Hz NTSC (the Paula rate of period 428); `sample_rate` carries it | rate and base-note policy: Q3, settled in M2 (section 8) |
| multi-octave 1–6, 7 | v1: the longest octave as the single sample, the instrument's `tune` landing it on the unity note (section 8); Amiga mode keeps N samples + key map (needs the Amiga instrument block) | slots for N separate instruments do not exist (63 + extras > 64) |
| synth −1, hybrid −2 | v1 *inference*: first waveform as a looped single-cycle sample (hybrid: its sample), tables dropped and reported; v2: `medsynth` SD module (engine FX 128+cmd, section 4) running the two tables per tick | radar `tracker-module-import` options a/b/c; maintainer picks (Q6) |
| MIDI (`midich` ≠ 0) | kind MIDI, channel `midich`; `midipreset` → program; `svol` → velocity | MIDI commands: section 4 |
| `svol` 0–64 | instrument level on the 1.2+ law (OS-BUG-PASTE24): svol 64 is level 50 (0 dB), lower values at their ratio in dB, 1–4 are level 1, 0 is 0; the Amiga engine reads it back within 1 of svol (volumes 1–2 read 4, 59 reads 61) | |

Amiga mode needs u32 loop fields: instrument-format bump |
| `InstrExt.finetune`, `hold`, `decay`, `default_pitch` | Amiga: PT finetune table (exact), hold/decay engine; Modern: fine tune ±12.5 cents per step *inference*, amp-envelope hold/decay (OpenMPT does the same `[S9]`) | `default_pitch` sets the note used when a cell has an instrument but no note |
| name (`MMDInstrInfo`, 40) | name ≤ 32 | |

### 3.4 Notes, volume, pan
- **Note byte (settled in M2, section 8):** MED note *n* (1 = C-1) → our byte `n + 48 + playtransp`, `n + 24 + playtransp` in MMD3, which is OpenMPT's own note number and puts a type-0 sample's unity (MED C-2, n = 13) on this OS's sampler unity byte 61. The first draft of this section said `n + 12` (libxmp's pattern offset, which is not a pitch rule); the per-kind unity notes are measured, not read: table in section 8. Out of 1..128 the note is dropped and counted. OpenMPT folds out-of-range notes by octaves "for 4-channel modules" `[S9]`; we report instead.
- **Volume (settled in M2, section 8, open item O12):** MED has no volume column; the note volume is the instrument default until `0C`. `0C` goes into the model's volume byte: decimal-coded (`(d>>4)×10 + (d&15)`, above 64 clamped and counted) unless the song says `FLAG_VOLHEX`, in which case libopenmpt 0.7.3 reads it as 7 bit (`((v&0x7F)+1)/2`, so `0x7F` is full and `0x40` half), and so does the importer, keeping `d & 0x7F` as the model's 0..127. The draft said "hex 0..64" (a libxmp quote); the extension table of the block does not switch anything in libopenmpt. Decimal: `v127 = min(127, 2 × v64)`, back `v64 = (v127 + 1) >> 1`: exact round trip of 0..64.
- **Cell commands:** command 1 → `fx[0]`, extra page commands → `fx[1]`; a third command is dropped and counted (OpenMPT moves it to the next row `[S9]`, which changes timing).

### 3.5 Tempo → our 192 PPQN grid
Our step = one line = 15 / BPM seconds (ADR 0013 D5: 4 steps per beat, 48 microsteps per step). MED line time = `tempo2 (SPD) × T_tick`. **Fact** `T_tick`:
| Mode (flag) | `T_tick` seconds | Source |
|---|---|---|
| Speed (default), tempo > 10 | 474,326 / (CIA clock × tempo); CIA = 709,379 Hz PAL, 715,909 Hz NTSC; libxmp and OpenMPT use ≈ 0.66 / tempo (BPM = tempo / 0.264) | `[S11]` numbers (GPL-3.0-only code, values only), `[S9]` |
| Speed, tempo 1–10 | tempo / 293.7 (measured; ideal 300) | `[S11]`; OpenMPT `6 × 1,773,447 / 14,500 / tempo` BPM, same |
| 8CHANNEL, tempo 1–10 (above = 10) | 2.5 / BPM8, BPM8 = 179, 164, 152, 141, 131, 123, 116, 110, 104, 99 | libxmp and OpenMPT agree (provenance may be shared) `[S4, S9]` |
| BPM (`flags2` 20) | 10 / (BPM × lines-per-beat), lines-per-beat = (`flags2` & 1F) + 1 | `[S11]`; OpenMPT `BPM × lpb / 4`, comment "ticks per row still influence the tempo" `[S9]` |
8CHANNEL wins when both flags are set (OctaMED 4.03–SoundStudio 1.03, OpenMPT r13787 `[S10]`); with mixing and tempo < 8, OpenMPT uses a fixed 157.86 BPM `[S9]`; `0F01`/`0F02` in BPM mode reset to 112 BPM in OctaMED 5 `[S10]`. **Conflict:** `[S11]` gives 8-channel `T = min(10, tempo) / 390.7` (2.56 ms at tempo 1) against the table's 2.5 / 179 = 13.97 ms; they agree only at tempo 10. We use the table (two independent readers, tuned by ear) and keep the formula as an unresolved oracle item (Q5).
**Conversion:** `BPM_ours = 15 / (SPD × T_tick)`; in BPM mode this is `1.5 × BPM × lpb / SPD`. Worked arithmetic (checked by hand):
- speed mode, tempo 33, SPD 6, PAL: T = 474,326 / (709,379 × 33) = 0.020262 s, line = 6 × T = 0.121573 s, **123.39 BPM** (NTSC clock 124.51; the 0.264 convention 125.00);
- BPM mode 125, lpb 4, SPD 6: T = 10 / (125 × 4) = 0.02 s, line 0.12 s, **125.00**; BPM 120, lpb 8, SPD 3: T = 10 / 960 = 0.010417 s, line 0.03125 s, **480 BPM**;
- 8-channel tempo 4, SPD 6: T = 2.5 / 141 = 0.017730 s, line 0.1064 s, **141.0**;
- out of range (SPD 1, 240 BPM, lpb 4: T = 10 / 960, line 10.4 ms = 1,440 BPM) clamps to 800 and is reported.
The initial tempo goes into `PHDR` (BPM × 100, exact to 0.01). Changes become **FX 15** with `value ≈ BPM / 2` (PAR-082: stored 4–200, displayed 8–400; the ×2 is an *inference*; range 5..200), quantised to 2 BPM, so the error is ≤ 1 BPM (0.8 % at 125 BPM): a fine-tempo core FX is optional (section 4, id 44). SPD changes (`09`) emit **core FX 43 Speed** (ticks per step, resolution only) plus the matching tempo change. Default clock PAL (same as the Paula pitch of `amiga-playback-mode`), NTSC as an import option (Q3).

### 3.6 Import report (never silent)
A fixed struct of counters, host-testable: dropped tracks (index, played cells, notes); `cmd_dropped[256]` and `cmd_approx[256]` (count per MED command byte); per instrument the fallback used (synth, octave collapse, loop quantised, 16-bit, packed or oversize refused); tempo clamps (count, first line); notes out of range; third commands dropped; flow (loop point found, segments emitted, patterns used of 128, order entries of 255, structural fallback taken); ignored data (echo, `voladj`, notation, ARexx, MIDI dumps, annotation, extra songs). The UI shows a one-screen summary and writes the report beside the project (radar UX sketch).

## 4. Command mapping
`E<n>` = engine FX type `128 + n` of the Amiga/MED engine (n = MED command 00–3F, so the window 128–191 holds every MED command verbatim, value = the MED data byte). *Inference/proposal*: ADR 0004 reserves 128–255 for the instrument's engine through the module ABI; the Amiga voice is core (ADR 0013), so a core engine declaring a table needs a maintainer nod (Q1). The same window can serve ProTracker MOD import (E1x → `E11`, E2x → `E12`, E5x → `E15`, E6x → `E16`, E9x/EDx → `E1F`, EAx → `E1A`, EBx → `E1B`, ECx → `E18`, EEx → `E1E`). The importer emits the OG/core target when the cell's instrument is **not** Amiga-engine and `E<n>` when it is (this OS clamps the values of those FX at use). Exactness: **exact** = same audible result by construction; **approx** = nearest representable, counted in the report; **drop** = counted. ### 4.1 Where libxmp and OpenMPT differ (quirks to expect, all **Fact** unless marked)
- **Command pages:** OpenMPT reads and merges them (overflow to the next row); libxmp skips them `[S6, S9]`. **Play sequences:** libxmp the first only, OpenMPT appends all; **extra songs:** OpenMPT chains them, libxmp ignores `[S5, S6, S9]`.
- **Tracks:** libxmp refuses MMD0/1 above 16 tracks, OpenMPT accepts more for MMD1 (SoundStudio 1.03 writes them); both stop at 64 `[S5, S9]`.
- **Vibrato `04`:** libxmp uses a double-depth vibrato, OpenMPT doubles the depth nibble capped at F `[S4, S9]`. **Hold/decay `08`:** libxmp counts it per tick with version quirks (retrigger extends the hold from OctaMED 3.00; "note delay doesn't delay the hold?"), OpenMPT builds an envelope for samples `[S7, S9]`.
- **Tempo:** `0F01`/`0F02` reset to 112 BPM in OpenMPT (OctaMED 5 behaviour), libxmp does not; OpenMPT clamps MED tempos below 32 BPM to 32 because MOD/XM treat them as tempo slides `[S10]`.
- **Sample offset / reverse:** `20 00` reverse only with a note in both; `20 xx` skip is unimplemented in OpenMPT; `29` exists only in OpenMPT `[S4, S9]`.
- **Misc `0F` and MIDI:** OpenMPT maps `0FF8/F9` (filter), `0FFD` (set pitch), `10` and `1C` (MIDI); libxmp discards all of them, plus `0E`; both ignore `0FFA/FB` and `0FFE` (end of song), so an oracle run keeps playing past an `0FFE` `[S4, S9]`. **Volume `0C`:** both honour `FLAG_VOLHEX`; OpenMPT detects 7-bit volume from the presence of the `cmdExt` table (*inference* by the OpenMPT authors: "closest we have to identify it") `[S9]`.
- **Synth:** libxmp plays the tables in its own player; OpenMPT translates them to synth-script events since 1.32 (r20583, April 2024) `[S7, S10]`.

## 5. Playback faithfulness (Amiga/Paula mode)
Classes by file: **A** hardware 4-channel (MMD0/1/2, no `MIX`, ≤ 4 tracks): Paula mode, exact target. **B** OctaMED 5–8 channel (`8CHANNEL`): OctaMED mixed two tracks per Paula channel in software `[S13]`; Paula mode with 8 independent voices L R R L L R R L is **approx** (mixing rate, volume scaling and the tempo table differ in the original). **C** SoundStudio mixing (`MIX`, MMD2/3, up to 64 tracks, 16-bit, stereo, echo): not Paula; play in the Modern engine, echo and stereo separation reported. Mode choice per instrument (radar): classes A and B import instruments as Amiga engine.
**Paula mode must emulate** (beyond `amiga-playback-mode`):
1. Integer periods from a 16-finetune × 36-note table (C-1..B-3), minimum period 113 on hardware and 55 in mixing songs (OpenMPT `55×4` vs `113×4` `[S9]`); notes beyond three octaves use the multi-octave samples.
2. 8-bit data, volume 0–64 without PWM, loop reload at the end of a cycle, `replen ≤ 1` = one-shot.
3. The tick engine: `SPD` ticks per line; tick 0 applies note, instrument and volume, then effects; slides also run on tick 0 when `STSLIDE` is clear (libxmp `QUIRK_VSALL|PBALL` `[S5]`); vibrato from a 32-entry sine, depth doubled for `04`; hold/decay counted in ticks, and from OctaMED 3.00 a retrigger adds the current tick to the hold counter `[S7]`; `0FF3` retriggers every 2 ticks (libxmp: "OctaMED ≤ 4.00 bug (TODO: verify)" `[S4]`).
4. The filter flag and `0FF8/0FF9` driving the A500 LED filter.
5. **PAL vs NTSC:** libxmp plays MED with C4 = 8,363 Hz (`C4_NTSC_RATE`) `[S5]`; the pt2-clone Paula is PAL 3,546,895 Hz (period 428 = 8,287 Hz, radar). They are 1200 × log2(8363 / 8287.1) = 15.8 cents apart, so oracle comparisons use a tolerance or configure the clock.

**Cost, *estimate*:**
- Tick processor ≈ 120 cycles per track per tick, 8 tracks × 120 = 960 cycles per tick. Typical 50 Hz tick: 48,000 cycles/s = 0.027 % of 180 MHz. Worst case, speed-mode tempo 240: 240 / 0.66863 = 359 Hz × 960 = 344,640 cycles/s = 0.19 %. The voices are costed by ADR 0013 (Paula B 1.1–2.8 % each). Core code ≈ 2–3 KB (*inference*).
- Import: 32,768 cells × 200 cycles = 6.6 Mcycles = 36 ms (radar figures); flow pass ≤ 65,536 visits × 8 tracks × 20 cycles = 10.5 Mcycles = 58 ms; SD I/O dominates.
- Reader RAM 788 + 1,020 (block table) + 252 (instrument table) + 256 (line) + 512 (report counters) = 2,828 B, so a 4 KiB budget.
- Flash if built on libxmp-sized code: 62,802 B of MMD loaders × 0.25–0.4 = 15.7–25.1 KB plus an 8–15 KB mapping layer (radar rule and figures); a thin own reader should be smaller (*inference*). As an SD importer plugin (ADR 0002) that is 0 B of core flash; only the tick processor lives in core.

**Oracle options (host only, unit tests):**
1. **libxmp event oracle:** `xmp_play_frame` + `xmp_get_frame_info` give per tick `row`, `frame`, `speed`, `bpm` and per channel `period`, `volume`, `pan`, `note`, `instrument` `[S8]`. Compare our tick processor's period and volume streams on synthetic modules, not audio. To keep libxmp out of the repo and CI, generate golden streams once on a developer machine and commit small text files plus the generator script (the MIT notice applies if code is vendored).
2. **libopenmpt pattern API** (`openmpt_module_get_pattern_row_channel_command`) as a second opinion for the **import cell mapping** only (it converts MED to MOD-like effects).
3. Formula tests for 3.5 (the arithmetic in the test itself).
4. Local fixture survey of the maintainer's modules (skipped when absent; counts and no-crash only, as OS-004b).
5. A/B listening on the device (HW-B).

**Blind spots to avoid:** libxmp reads one play sequence, no command pages, no extra songs, ignores echo, stereo separation, free pan and volume adjust, and plays synth vibrato as a sine `[S4, S6, S7]`; OpenMPT turns hold/decay of samples into an envelope and puts overflow commands on the next row `[S9]`; both discard MIDI and undefined commands. Where oracle and spec disagree the test records the divergence, it does not hide it.

## 6. MED export
**Feasible, lossy by design; recommended as the last slice (M5), narrow, and not promised as audibly faithful.** Target: **MMD1** for ≤ 8 tracks (hardware or 8-channel; the widest player support: OctaMED, libxmp, OpenMPT), **MMD3 with `MIX`** for 9–16 tracks (the format SoundStudio writes in mixing mode; pattern note numbers 24 lower `[S9]`). Not written: MMD0 (4-bit commands), MMD2, synth, command pages, MIDI. Lost: about half of the 43 OG FX types have no MED command (*inference* from section 4: sends, filters, slices, granular, chance, random, MIDI CC, most LFOs), 192-PPQN microtiming (Roll → `1F`/`0FF1`/`0FF3`, Micro-move → `1F` delay, nearest tick), per-track lengths (a block has one length: pad to the longest, or expand to the common multiple, *inference*), tempo to the MED model (BPM mode, lpb 4, SPD 6, one BPM per change), samples (44.1 kHz 16-bit → 8-bit at an Amiga rate, or 16-bit `S_16` in MMD3), sampler modes, envelopes and filters, instrument names beyond 40 characters. Effort *estimate*: writer ≈ 600 lines + resampler reuse + tests; validated by our reader, libxmp and OpenMPT as structural readers; audible validation needs OctaMED itself (maintainer, emulator). Recommendation: **yes, after reader, mapping and playback, with the drop report mirrored**; no if the maintainer's goal is only to *play* MED songs.

**Open, need a source or a real file:**
- **O1** Layout and meaning of the `cmdExt` table (BlockInfo offset 16). **Resolved in M0 on OpenMPT's reader `[S9]`, pinned by tests, to be confirmed on a real SoundStudio file:** BlockInfo offset 16 holds a pointer to a u32 that points to the table; the table is `tracks × lines × (1 + pages)` bytes, one extension byte per cell, the default page first and then each extra page in order, every page line-major (`MMDBlockInfo::cmdExtTableOffset` and the block-reading code of that reader: `file.Seek(file.ReadUint32BE)`, `ReadChunk(numTracks * numRows * (1 + numPages))`, bytes consumed in cell order of the default page and then of each page). The reader exposes it as `Cell::ext`.
- **O2** How `0A` differs from `0D`. **Narrowed in M1:** libxmp calls `0A` "not mentioned but it's Protracker-compatible" and maps `0A` and `0D` to the same volume slide, OpenMPT does too `[S4, S9]`; M2 treats them alike. A difference inside OctaMED itself would show only against the program.
- **O3** Unit of loops in 16-bit samples (bytes or samples) and of the V7 `long_repeat`. **Resolved in M0 on two readers:** frames. libxmp halves only the length of a 16-bit sample, commenting "the loop is measured in sample frames", and takes `rep << 1` and `long_repeat` as frame counts; OpenMPT does the same (`rep × 2`, `long_repeat` as a sample position) for 16-bit data `[S4, S9]`. `InstrumentInfo::loop_start` / `loop_len` are in frames of the shortest octave.
- **O4** What `0F F4–F7`, `FC`, `21–28`, `2A–2D` are, if anything.
- **O5** The exact note-to-pitch octave per instrument type and file version (3.4).
- **O6** The SoundStudio 1.03c manual (Modding Fridays, `[S16]`) was **not readable** here. Command semantics above come from libxmp and OpenMPT comments and a forum quote of the V5 manual `[S12]`; reading the manual is a prerequisite of slice M3.
- **O7** Which MMD version OctaMED 8 (2024) writes.

**Status after slices M0 and M1 (OS-008a, `formats/med`, 2026-10-11).** O1 and O3 are resolved as above, O2 narrowed, O4 to O7 unchanged (no readable source describes `0F F4–F7`, `FC`, `21–28`, `2A–2D`). Numbers corrected by exact integer arithmetic in the 3.5 conversion (the tests pin them): speed mode 33 / SPD 6 / PAL is **123.38 BPM** (123.383; the 123.39 above is a rounding slip) and NTSC **124.52** (124.519). The sample-arena budget of 2.6 item 6 is **10,816 KiB** (ADR 0013 amendment 1), not 11.19 MiB. Found while implementing and not settled by any source I could read:
- **O8** `0B xx` and the Jump command of a play sequence in a song with several sections (MMD2+): the position is taken **within the section being played** (all of the sequence for MMD0/1 and for one section), the Jump target likewise; OpenMPT appends the sequences with a separator row and uses the position in that concatenation `[S9]`. The two agree for one section. Needs a real multi-section file.
- **O9** BPM mode with a tempo below 7: OctaMED 5 and SoundStudio 1.03 do not play the nominal value (OpenMPT uses 111.5 BPM, `0F01`/`0F02` give 112) `[S9, S10]`; the importer plays the nominal value and counts these (`FlowReport::tempo_suspect`).
- **O10** `1D xx` (and `0F00`): xx is **hex** (V5 manual `[S12]`, OpenMPT `[S9]`); libxmp reads the byte as BCD `[S4, S5]`, so `1D 10` is line 16 here and line 10 there. When `0B` and `1D` share a line the position comes from the first and the line from the second (ProTracker); libxmp lets `0B` reset the line.
- A module whose smplarr is 0 with `numsamples > 0` keeps its instruments outside the file (OctaMED Pro MMD1 `[S1]`): the reader refuses it as Unsupported.
- **O11** Whether the InstrExt loop flag applies to MMD0/MMD1 files. libxmp reads `SSFLG_LOOP` only when `ver >= 2 && s_ext_entrsz >= 8` (an MMD0/1 file loops when `replen > 1`, whatever InstrExt says); OpenMPT reads it whenever the InstrExt entry reaches the flag byte, for any version `[S4, S9]`. The reader follows libxmp's version gate with the stride rule of 2.6 (the flag needs stride >= 6) and passes the raw byte on as `InstrumentInfo::ext_flags`, so M2 can choose. Needs a real MMD1 file from OctaMED 5 or later whose loop flag and `replen` disagree.

**Decided in the review of OS-008a (2026-10-11).** (1) `16 xx` and `1E xx` take the whole data byte, up to **255** repeats, as OctaMED allows; the 15 in 3.2 and 4 is libxmp's and OpenMPT's, a limit of their 4-bit E6x / EEx conversion `[S4, S9]`. 255 repeats of a body need 256 order entries, so such a loop ends in LimitExceeded and the structural fallback or "first N order entries" of 3.2 apply, as for any song that is too long. (2) The visit cap of 3.2 is **32,640 lines** (255 order entries of at most 128 lines: a song the model can take never needs more; 65,536 could not be reached), and the work is also capped in **cells** (tracks × (1 + command pages) per line, default 2^21), so a block built to be slow (64 tracks, 9,999 lines, 16 shared pages) is refused after 1,928 lines. The flow runs as a resumable job (`FlowJob::step(budget)`). (3) Bit 7 of an MMD1 note byte is passed on as `Cell::note_hi` instead of being masked away: OpenMPT reads a note byte of exactly 0x80 as a note cut `[S9]`, the layout document calls the bit reserved `[S1]`; the mapping decides.

**Status after slice M2 (OS-008b, `formats/med/map.h`, `import.h`, 2026-10-11).** The importer is a resumable job (`med::Importer`: open, validate in chunks of 64 units, flow, scan, header, instruments, patterns, order; one line or one instrument per tick) and a registered `FormatReader` ("med", FormatKind::Project, `.med .mmd .mmd0 .. .mmd3`, sniffed on `MMD0`..`MMD3` with room for the header and the song). A module is a graph of offsets, so it needs `ReadParams::random` (the file as a `RandomSource`); without it the strategy fails with Internal. The PCM is not written by the job: the platform makes `samples/instrNN.wav` (NN = the MED number, the name this OS and the WAV importer give the slot) from `Importer::read_pcm` (16-bit mono) at `pcm_rate()`. `ImportReport` holds every counter of 3.6 (per command dropped and approximated, per track cells and notes and slot, per instrument result and flags, the `FlowReport`, ignored data, clamps); `FormatReport::dropped_groups` names what the model could not keep (`drop_group_name`). A failed import leaves the project reset (valid and empty). The scan and the mapping pass each stop at a cell cap of their own (`ImportOptions::max_scan_cells`, `max_map_cells`, the flow's 2^21 by default). Code ≈ 9.7 KB of MK66 library text at -Os (the skeleton image does not link `formats` yet), RAM about 13 KB for the job (`BuiltinFormats` grows by that). Tests: `med_map_test.cpp`, `med_import_test.cpp` (host and QEMU, thinned there), `med_import_big_test.cpp` (host, with the import job of the app), ctest `med_import_python` (the reference modules of `mmd_build.py` through `o3med_tool import`, instrument by instrument against the Python description), and the libopenmpt oracle `med_openmpt_oracle.py` (ctest `med_openmpt`, skipped without the library unless `O3_CI=1`, which `ci.sh` sets and the workflow's libopenmpt install satisfies). A local survey of real modules runs when `O3_MED_DIR` names a directory of them (counts printed, never names or notes); none was available when M2 was written.

**Status after slice M3 (OS-008c with OS-005h, `audio/med_tick.h`, `amiga_voices.h`, `paula.h`, 2026-10-12).** The tick processor is a pure integer state machine per track (`med::Track::tick`), in the audio layer (it consumes audio events; the audio layer may not include the sequencer or the formats), driving a Paula channel (`paula::Channel`, a float re-implementation of pt2-clone's model, bit-exact against the original in `tests/paula_oracle_test.cpp`). Implemented: 00 arpeggio, 01 / 02 slides, 03 tone portamento (03 00 continues), 04 / 14 vibrato (04 twice as deep), 05, 06, 07 tremolo, 08 hold and decay (beside a note), 0A / 0D, 11 / 12, 15, 18, 19 (sample offset), 1A / 1B, 1F (delay and retrigger), 0F F1 / F3 (retrigger), F2 (delay 3), F8 / F9 (LED filter), FD (set pitch); core FX 43 (ticks a row) arrives as the Tick event. **Oracle:** libxmp (MIT) at commit 5d4f6aa2c7, hand-built outside the repository; `tools/med_tick_golden.py` writes 27 one-track MMD1 scenarios and records its period, volume and restart per frame into `tests/data/med_tick_golden.txt`; 1,872 comparisons, volume and restart exact, period within 1.0 (exact except arpeggio and two notes, where libxmp's float period differs from the hardware's integer table by under one unit). Where the oracle and the design differ: the period is held to Paula's 113..65535 (libxmp keeps no range for MED and goes silent below 0.25); hold symbols (an instrument number on the next row sustaining the hold) are not modelled; the second FX column is not in libxmp's reading (command pages are not read by it), so it is held by formula tests only. **How a command runs:** the step FX window `128 + command` holds until its column's FX changes (`seq/control.h`), so it runs on every row like a MED command repeated on every row; a note step ends both columns itself; the importer therefore writes `E00 00` ("no effect") in a free column on the row after a command (`ImportOptions::engine_fx`, the registered "med" reader has it ON by default, `Importer` OFF). A column that holds another FX on that row cannot say it (rare, not counted). **Not done:** 0C without a note (a persistent volume override: the voices do not read the Volume group), 1E, 20 reverse, 29, E0E and every other command of the section 4 table without an engine entry; the Amiga instrument's multi-sample octave map; the instrument hold/decay (O16). **Engine choice:** `SampleDesc::engine` (Modern, Amiga, 12-bit, 8-bit) is runtime only; `app::SampleBank::engine_for` gives Amiga to a sample instrument that plays as a one shot or forward loop and carries the Paula rate 8,287 or 8,363 Hz (what the importer's WAVs carry, so it survives a save) and Modern to the rest, with `set_engine` and `set_amiga_by_rate(false)` as the reversible overrides; persisting the choice needs an INST 1.x minor field and a loader (maintainer decision, not done). An import with `engine_fx` OFF (the dialog's Modern choice) writes its sample instruments MODERN, because the Paula rate would send an AUTO instrument to Amiga at the load (OS-BUG-MODENGINE). **Default filter** on the Amiga voices is the Amiga 1200's (5.3 Hz high-pass, no audible low-pass); A500 and the LED filter are `AmigaVoices::set_filter`, and the song's 0F F8 / F9 switch the LED.

**Measured with libopenmpt 0.7.3** (`o3med_tool import` against the library loaded by ctypes: 2,538 comparisons, none apart; nothing vendored; at least 2,400 and libopenmpt 0.7 or newer are asserted). Each row is a rule of the importer that the program confirms or that the program forced:

**The conversions M2 chose where the table of section 4 left a number open** (each is counted in `cmd_approx` unless it is exact; the maintainer may veto any):
| MED | OG / core value |
|---|---|
| `01` / `02 xx` | 41 / 42, `xx` verbatim (unit unconfirmed, PAR-079) |
| `03 xx` | 19 Glide: the time a slide of one octave (428 to 214) takes at `xx` per tick, from the tick time of the tempo in force, on the Glide FX's scale (preset 0..50 = 0..1000 ms, 50..100 = 1000..15000 ms); `03 00` (continue) dropped |
| `04` / `14 xy`, `07 xy` | 33 / 23: rate preset `round(x × 28 / 15)` / `round(x × 23 / 15)`; the depth is the instrument's LFO |
| `09 xx` | Tempo for (tempo, xx) then core 43 Speed `xx`; with one free slot, the Tempo |
| `0F tt` | 15: `round(BPM / 2)` clamped to 5..200 (counted), and core 44 Tempo fine `128 + round(4 × (BPM − 2 × value))` when a slot is free: error at most 0.125 BPM |
| `0F F1` / `F3` / `F2` / `FD` / `FF` | Roll 2 / Roll 3 / Micro-move 50 / Glide 0 / note cut when the cell has no note |
| `15 xx` | 34: `99 + round(12.375 × ft)`, ft = −8..7 (−8 → 0, 7 → 186) |
| `18 xx` | 20: `round(100 xx / SPD)` |
| `19 xx` | 22: `round(100 × 256 xx / frames)` of the cell's instrument, else the one the track played last in the piece, else dropped (`state_unknown`) |
| `1A` / `1B xx` | volume column baked from the track's volume in the piece (instrument default or last `0C`), else dropped |
| `1F xy` | Roll for y ticks (nearest of the eight periods) and Micro-move `round(100 x / SPD)`; nothing without a note |
| `20 00` / `29 xx` | 26:1 with a note / 22: `round(100 xx / ext)` (dropped without the extension byte) |
| `2E xx` | 31: `50 + round(v × 50 / 16)`, v signed and clamped to ±16 |
| `31..35 xx` | CC A..E for a MIDI instrument (`min(xx, 127)`), else dropped |
| `0B`, `16`, `1D`, `1E`, `0F 00`, `0F FE` | nothing: the flow has done them. In the structural fallback `0F 00` and `1D` are Break Pattern, `0B xx` core 45 Order jump (xx ≤ 254, approximate: the order counts the pieces the fallback cut), the rest dropped and counted |

State (tempo, speed, per track instrument and volume) restarts at each piece, which is the unit the flow keys its patterns by; a piece that sets no tempo or speed uses the song's start, so `18` and `1F` in a shared piece see the speed at the start of the song (approximate if a `09` changed it earlier).

**Q1 to Q7 as built.** Q1: the engine window is written by `engine_fx` (the Amiga engine itself is M3). Q2: core FX 43 and 44 are written, 45 Order jump by the structural fallback for `0B`. Q3: PAL by default, NTSC an option for both the CIA tempo and the Paula rate; native-rate WAVs with the note transposition of the table above. Q4: `Overflow::Refuse` (LimitExceeded and `ImportReport::overflow` plus the flow counters, so the UI can offer the others), `Structural`, `Truncate`; more than 16 used tracks keep the busiest 16 (ties: the lower track), in MED order, never folded; the lost ones are in `track[]` (cells, notes). Q5: the table of 3.5 (M1). Q6: v1 as 3.3: a synth instrument is its first waveform as a looped single cycle, a hybrid its sample, the tables dropped and flagged. Q7: M5.

**Open items after M2.** O1: libopenmpt 0.7.3 does not change the volume by the extension table; its use by `20` and `29` still needs a real SoundStudio file. O3: resolved in M0 (loops are in frames); the importer writes them as fractions of the shortest octave's frames, so any octave gets the same positions. O2: `0A` and `0D` are the same volume slide in both readers (CMD_VOLUMESLIDE); both dropped in the OG column, `E0A` / `E0D` in the engine window. O4: `0F F4..F7`, `FC`, `13`, `17`, `21..28`, `2A..2D`, `2F`, `30`: dropped and counted (kept raw as `E<n>` with `engine_fx`). O5: **settled** by the table above. O6, O7: unchanged. O8: unchanged. O9: the nominal value is played, `ImportReport::flow.tempo_suspect` counts them. O10: hex, libopenmpt agrees. O11: **settled** (OpenMPT's rule, flagged where libxmp differs). New:
- **O12** `FLAG_VOLHEX` scale: the document and the libxmp quote say hex 0..64, libopenmpt reads 7 bit (0x40 is half). **Decision (maintainer, review of OS-008b): follow libopenmpt (7 bit), revisit if a real module disagrees.** A wrong choice halves, or saturates, the volume of every hex-volume song; libxmp or OctaMED would arbitrate.
- **O13** Does the step's volume column replace the instrument's volume (as MED's `0C` replaces `svol`) or scale it? The importer writes the instrument's `svol` as the instrument volume and `0C` into the column; the engine (OS-005) decides what that means.
- **O14** Pan without a pan table: MMD0/1 and MMD2+ songs without `MIX` get Paula's hard L R R L (classes A and B of section 5), mixing songs the centre. Inference.
- **O15** The unity of synth and hybrid instruments (n = 37, tune −24) comes from libxmp's `12 + strans`; libopenmpt 0.7.3 has no synth player to measure. Inference.
- **O16** `default_pitch`, hold and decay are not mapped (libopenmpt ignores `default_pitch` for a cell without a note; the amp-envelope units of the OG are not sourced); both are flagged per instrument.
- **O17** The values chosen above for `03`, `04`, `07`, `15`, `18`, `19`, `1F`, `2E` and `31..35` are conversions, not facts.
- **O18** Track names (SoundStudio 2) and a maintainer-chosen set of 16 tracks (the report has the data, the option is not built).
- **O19** The per-track state (instrument, volume) restarts at each piece, so a volume that a `0C` gave in one block and that the next block's first bare note inherits is not carried across the boundary (the flow keys patterns by tempo and speed, not by volume); within a piece it is exact (`volume_baked`).
