# OS-SCRATCH: the DJ page scratch feel

Level C (audio render path). Status: design, then as built (section 5). Amends OS-DJ section 2.6 (C1); the C1 text stays the record of the first build. Behaviour: `new Community OS behaviour`, nothing is measured on an official unit. The feel is judged by ear on the unit (OS-DJ R2).

## 1. Today (C1)

`MasterScratch::next_rate()` (audio/src/master_scratch.cpp), Platter phase, once a block (64 frames, 1.45 ms):

1. `hand` = signed 16-bit difference of the FTM2 counter since the last block, clamped to +-16.
2. `raw = hand * kCountRate` (one count is 827 frames, so one count in a block is rate 12.9).
3. `rate = rate + (raw - rate) * 0.28` (one-pole, about 3 blocks = 4 ms), snapped to 0 under 0.001 when `hand == 0`.
4. The block ramps the rate linearly from the old to the new value; `lag += 1 - rate` per frame; the read is linear between two frames, times the gate `min(8 |rate|, 1)`.

Why it feels rough: the velocity is "counts in this block", an integer 0, 1, 2, ... A hand turning at 1 count per 20 blocks (a slow, normal scratch) is a rate of 12.9 for one block and 0 for 19: pulses, not motion. The 4 ms smoothing does not bridge them. The stop is a step for the same reason. The read is linear, which dulls and aliases the sound when the head moves slower than real time.

## 2. Where the velocity comes from (a deviation from the brief)

The brief suggested timestamps from the main loop passed to the render through the command path. The scratch has no such path: OS-DJ Q8 chose "the render reads FTM2 `CNT` once a block" over "the main loop's events through a queue", and the encoder events the main loop sees are detents (4 counts), coarser than the counts. The render already runs every 1.45 ms, which is the timestamp: the block index. So the inter-count timing is measured in the render, in blocks, from the same counter read, with no new cross-thread state (everything below is render-owned; the app and the platform are untouched). A 1-block quantum is 7 % of a 1-count-per-14-blocks turn and 1.5 % of the 4-count span used below.

## 3. The change

> Superseded in part by section 8 (OS-BUG-SCRATCH): the inertia, the gate slope, the ahead and the history there are the current values.

All of it only in the Platter phase (and the Spin and Release that follow a Platter); TAPE STOP (modes 2 and 3) keeps its code path and its output bit for bit.

- **Velocity from timing.** The last 4 count events (a block with `hand != 0`: its block index and its count) are kept. `v = (counts of the 3 newer events) / (block index of the newest - block index of the oldest)` counts per block, about one detent of history, so the snap of a detent does not show. One event alone (a start, or the first after a reversal) counts as 1 count per 8 blocks. A reversal clears the history and the position debt (below): the head follows the new direction at once, not after the hand has travelled back over the old direction's unplayed counts (a clamped flick leaves up to 8). The estimate is capped at `1 / age` counts per block while `age` blocks have passed since the newest event (no event for a long while means slowing), and it is 0 after 96 blocks (139 ms) without an event.
- **Position kept.** An estimate does not add up to the hand exactly, so a `debt` (frames: the hand's counts times 827, minus what the targets have already played) is kept. The target never takes the head more than `kAhead` = a quarter count beyond the hand's last count (the hand is somewhere inside the count; a lone count moves the head one and a quarter counts at most, and a stopped hand leaves it at most that far ahead), by capping the block's rate at the rate that spends exactly the room left. A debt of more than one count is paid back at 1 / 4410 per frame, but the pay-back never lifts the target beyond `max(the hand's own rate, kPullMax = 1)`: a steady hand is not overshot, the surplus is paid when the hand slows or stops. The head follows the hand to within one count at rest (18 ms of audio), as before.
- **Inertia.** `rate += (target - rate) * kInertia`, `kInertia = 0.0564` per block, a one-pole of 25 ms (`1 - exp(-1.4512 / 25)`), a constant. A stop or a start is a curve of about 25 ms, not a step. The snap to exact 0 stays (under 0.001 with a target of 0), so a held record is exactly silent.
- **Backspin latch.** It used the smoothed rate; with 25 ms of inertia the rate lingers after a stopped hand, so the latch now also requires the hand's own target at or beyond -4 (`kSpinMin`): a hand that stopped dead for 30 ms releases, a fast backward flick spins.
- **Interpolation.** 4-point 3rd-order Hermite (Catmull-Rom) on the four frames around the head (one newer, two older), per channel, when the stage was started as a Platter. The newer tap is the head's own frame when it is the last one written; the older tap never needs a clamp (the lag limit already leaves it a written frame, and at the limit the fraction is 0, which reads exactly the frame). Estimated cost: about 35 cycles a frame against about 25 for the linear read, so +0.9 % of the CPU while scratching, 0 elsewhere (to be measured on the unit, cpu-budget section 5). Kept because scratching is a momentary, user-held state in the heavy-song headroom (17 %), and the pitch-down reads are where the linear read is worst.

## 4. Rules kept

> Superseded in part by section 8 (OS-BUG-SCRATCH): the inertia, the gate slope, the ahead and the history there are the current values.

No heap, no libm, no `double`; one loop of exactly 64 frames; one division and a few flops a block more. The code stays in flash (`O3OS_AUDIO_COLD`, -O3); `.ramfunc_l` is not touched. New state is render-only (set_mode, process: the ParamChange drain and the chain are one context, as before): about 48 bytes in `Graph::scratch_stage_`. No persistent format. Normal playback never reaches the stage (bypassed).

Tests (`tests/audio_scratch_test.cpp`): a rate curve for a synthetic count script (step response within a tolerance of the 25 ms constant, steady slow turn smooth, stop and start), a direction change without a click (bounded sample-to-sample delta on a sine), Hermite exact on a cubic and a constant, the position kept to one count, TAPE STOP identical to a linear-read reference.

## 5. As built

> Superseded in part by section 8 (OS-BUG-SCRATCH): the inertia, the gate slope, the ahead and the history there are the current values.

Files: `audio/include/o3os/audio/master_scratch.h` (constants `kInertia`, `kHist`, `kFirstSpan`, `kStopBlocks`, `kPull`, `kPullMax`, `kAhead`, `kDebtMax`; render-only members; public static `hermite4`), `audio/src/master_scratch.cpp` (`platter_target`, `next_rate`, the Hermite read), `tests/audio_scratch_test.cpp` (10 new cases). The app and the platform are untouched.

Changes against the design text found while testing (the code was wrong, the bounds are the design's):
- The first build stopped projecting only after the head was half a count ahead, evaluated before the block was played, so a fast hand that stopped dead left the head 2.4 counts ahead (the test "one turn": 1980 frames against a 1.5-count bound). The target is now capped each block at the rate that spends exactly the room left (`kAhead` = 0.25 count beyond the hand's last count). At rest the head is 0.25 count ahead of the hand (a lone count moves 1.25 counts).
- The position pay-back added to the target on top of a steady hand, so a step to a steady turn overshot the one-pole by 0.27 % and the trace was not monotonic. The pay-back is now capped at `max(the hand's own rate, kPullMax)`; a steady hand is the plain one-pole, the debt is paid when the hand slows or stops.

Results (2026-10-24):
- Host: `unit_audio` and the scoped host run, 301 of 301 ctest; e2e 76 of 76 (`O3OS_CI_BASE_BRANCH=merge/batch-0124b`). QEMU 60 of 60 (the `audio_limiter` suite runs `audio_scratch_test` on the target); MK66 19 of 19.
- TAPE STOP and every non-Platter path are unchanged from the base (abfcf51b). The first proof was a throw-away harness (the base and the new `master_scratch.cpp` over the same input, FNV-1a of the output bits, 7 of 7 identical at `-O2 -ffp-contract=off`); it is now in the suite, reproducible by anyone. Recipe: `ctest -R unit_audio` (and the target's `audio_limiter` suite) runs `scratch: TAPE STOP, modes 2 and 3, is the C1 linear path in 8 scenarios` in `tests/audio_scratch_test.cpp`. A `TapeRef` there mirrors the base stage's Tape / Release path float for float (same `advance_lag`, lag limit, gate, 256-sample release, mode 3 rebase) and runs beside the real stage on the ring it wrote, a 10 kHz sine in, compared sample by sample (tolerance 1e-4: a Hermite read would be off by about 0.1; the margin is for a fused multiply-add on the target, so no float-bit hashes are stored). Scenarios: 0.5 s, 1 frame, 2 s, encoder moving, mode 3 mid-brake, mode 3 after the stop, end mid-brake with mode 3 refused in the release, end after the stop; the rate and the return value of `set_mode` are compared too. The Platter's output differs, as intended. The older case `TAPE STOP is still the linear read of C1` keeps an independent double-precision reference.
- Review fold (2026-10-24): `debt_` is cleared on a direction change (the first build kept it, so after a clamped flick a reversal froze the head until the hand had come back about 8 counts; test `a reversal after a flick follows the new direction at once`: the rate is negative 16 blocks after the reversal, it was +1.35). The Platter's SCR-off decision after a hand that stopped dead is pinned by `SCR off after a hand that stopped dead releases ...` (40 blocks still: Release; without the `hand_rate_` condition: Spin; 10 blocks after a flick: Spin) with the release's sample step bounded.
- The entry (rate 1 to the still hand) reaches exact silence through the 25 ms one-pole after about 170 ms (119 blocks, the snap under 0.001), not the 10 ms of C1.
- Size, MK66 image against abfcf51b: FLASH +2,536 B (916,764 to 919,300 B; the debug and the qemu images the same), SRAM_U 0, SDRAM_STATIC 0, `.ramfunc_l` -8 B (27,292 to 27,284 B: layout of unrelated code, the stage is flash code).
- CPU: not measured on the unit (no scratch bench exists). Estimate +about 10 cycles a frame for the Hermite against the linear read, +0.9 % while scratching, 0 elsewhere. Unit: cpu-budget section 5 method on the bench image while scratching; 0 underruns.
- Unit by ear (OS-DJ R2), QA-PRF-150: a slow steady turn, a stop and a start, baby scratch forth and back, a backspin flick, a hand that stops dead and then SCR off (no spin).

## 6. The hand still (OS-SCRATCH-IDLE)

Unit measurement (fqa.12 bench, Dense8): SCR on with the hand still raised the CPU mean from 85.4 % to 90.3 % (+4.9 points; worst block 112.7 %, 0 underruns). The estimate of section 5 priced only the Hermite delta; the stage's fixed cost, paid at rest too, was not counted: it records every block into the ring (`write_block`, about 60 cycles a frame) and ran the 64-frame read loop (about 95 cycles a frame: lag limit, gate, `advance_lag`, the mix) even when the rate is 0 and the output is exact silence.

Fix (bit-exact, `new Community OS behaviour`: no change of sound): when the rate was 0 before the block and is 0 after it, and the stage is not in its release fade, the gate is 0 for all 64 frames, so `process()` writes 64 zeros per channel and only moves the lag (`still_lag()`: frame 0 through `advance_lag`, which rounds `lag_f + 1` onto the 2^-23 grid once; the other 63 frames are exact integer steps held by the same lag limit). Any non-zero rate, the release fade and the backspin take the per-sample loop as before. The ring is still written every block (SCR off and a hand that moves again read it). Estimated saving about 75 cycles a frame (about 5k cycles a block, 1.9 % of the 261k-cycle block budget by instruction count); flash +516 B, SRAM 0.

Tests: `scratch: a still hand takes the shortcut ...` (a mirror of the per-sample loop with the Hermite read and the real stage's rate, over a scratch that moves, rests, flicks, crawls, rests and releases, on the 2.5 s ring and the smallest ring: output and lag block by block); the eight TAPE STOP scenarios also compare the lag now. A throw-away A/B of the base and the new `master_scratch.cpp` (12 seeds x 4 ring sizes, FNV-1a of output, lag, rate and phase per block) gave 48 of 48 identical hashes. Unit: the bench image, Dense8, SCR on with the hand still, CPU mean to be re-measured (expected 2 to 3 points lower); the remaining fixed cost is `write_block`.

## 7. The hand still, second cut (OS-SCRATCH-IDLE2)

Unit (fqa.13 bench, Dense8): SCR on with the hand still 89.0 % mean (worst 108.8 %) against 85.6 % with SCR off: +3.4 points, about 8,900 cycles a block. Nothing outside `MasterScratch::process()` depends on SCR (the graph has no scratch branch beyond the chain slot). Static breakdown of the stage's still block (ARM -O3 disassembly times M4F timings, plus an x86 split of 47 % ring write, 21 % lag, the rest zeroing and glue; **estimates, the unit measures**): `write_block` about 4,200 cycles of float work (three float compares a sample for the clamp and the rounding sign) and 128 uncached SDRAM halfword stores (about 1,500), `still_lag` about 950, zeroing about 300, rate and glue about 550; flash wait states make up the rest of the measured figure.

Changes, both bit-exact and `new Community OS behaviour` free (the sound, the ring's contents and the lag are unchanged):
- `write_block`: a frame whose two samples are within |x| <= 2.0 (one integer test on the bit patterns; the clamp cannot act there) converts with `trunc(x * 16383.5 + copysign(0.5, x))`, the sign taken from the sample's bit; every other frame (a hotter sum, NaN, inf) takes the old conversion. The block is written in at most two runs (the ring's end splits it once: no wrap test per sample), and L and R go out in one word store when the ring is 4-byte aligned (half the SDRAM accesses), halfword stores otherwise.
- `still_lag`: the 63 frames after frame 0 in closed form. The loop is `L <- min(L, m_i) + 1`, `m_i` the read limit, non-decreasing by at most 1 a frame, so `m_i - i` never rises: the loop clamps at some frame iff it clamps at the last, and the lag after the block is `min(L1 + 63, m_63 + 1)`, the fraction 0 iff a clamp happened.

Tests (`tests/audio_scratch_test.cpp`, suite `audio_limiter`): the closed form against the per-sample loop on 900,000 random ring states (six ring sizes, lag around the limit, fractions on and off the 2^-23 grid); the ring against the old conversion over a sweep of the whole float bit space, the rounding ties, the clamp edges and the specials, at either alignment, across the ring's end. On the target (`__arm__`, the QEMU run) both sweeps are thinned to fit its heap and time: 6,000 ring states per ring size, and every 65,537th bit pattern; the tie, clamp-edge and special lists run in full. The golden hashes of section 6 are unchanged. Expected saving about 4,000 cycles a block (1.5 points) [est], to be measured on the unit (QA-PRF-150, Dense8 with SCR on and the hand still); flash +256 B on the release image (925,092 to 925,348 B).

## 8. The feel, second pass (OS-BUG-SCRATCH), as built

Level C (audio path). Maintainer, 2026-11-08: "the scratch sounds quite bad, it does odd things". Four causes found by reading the code against the count timing (a detent is 827 frames, about 13 blocks at 44.1 kHz, so a hand at normal speed makes one count every 13 blocks), `new Community OS behaviour`, host-proved, by ear still open:

1. **Stop-start.** `kAhead` was 0.25 count: the target was clamped to what the hand had already paid, so between two counts the head ran out and the rate fell to 0, at the count rate. Now `kAhead` = 1.0 count for two events or more (a lone count keeps `kLoneAhead` = 0.25: a click is a nudge); the velocity estimate is held for 1.5 times the last inter-event time (`kHold`: with no count for `age` blocks the estimate is capped at 1.5 / age counts a block) and then decays.
2. **Buzz.** The gate `g = min(8 |rate|, 1)` turned every dip of the rate into an amplitude change. A Platter run (also its Spin and Release) now has slope 32 (`kPlatterGate`: silent only under 1/32 of real speed); the TAPE STOP keeps 8 and its output is unchanged.
3. **Flutter.** The 25 ms inertia was shorter than the gap between detents, so the detent rate was audible. Now 70 ms (`kInertia = kBlockMs / (70 + kBlockMs)`; `kHist` 4 to 8 events, two detents of history). A reversal still drops the old direction's debt and the history at once, so the head follows the new direction from the first count back; a held hand still runs to exactly 0 (silence; about 340 blocks, 495 ms, from a rate of 1, and the entry run-down is longer than in section 5: its figures there are for 25 ms).
4. **Aliasing above rate 1.** A Platter run at |rate| > 1 reads through a one-pole low-pass per channel with the coefficient min(1, `kAaCut` / |rate|), `kAaCut` = 1.2, of the block's larger end rate. The state follows the read while the filter is bypassed, so at |rate| <= 1 the output is bit for bit the old read and the filter engages without a step; the state is zeroed in `set_mode`. TAPE STOP has none.

**Run-time tuning** (`MasterScratch::set_tuning(inertia_ms, ahead, gate_slope, aa)`, getters `inertia_ms()`, `ahead()`, `gate_slope()`, `aa()`; console `diag scratch` prints, `diag scratch <inertia_ms> <ahead_counts> <gate_slope> <aa 0|1>` sets; session only, never stored). Ranges 5..500 ms, 0..4 counts, 1..64, a flag; outside values and NaN are clamped. Protocol: the main loop is the only writer, the render reads each field once a block into a local; every field is a relaxed `std::atomic` (a plain aligned 32-bit load or store on the M4, 8-bit for the flag), so a block sees an old or a new value, never a torn one, and may mix fields (each is valid alone). No lock, no allocation.

Size: SRAM_L 0 B (the stage is in flash, `.ramfunc_l` untouched); new state in SRAM_U (four tuning words, two AA states). The idle path (a still hand with no AA) is untouched, bit-exact: the `audio_scratch_test` idle tests and the ring tests pass unchanged. Flash and SRAM_U deltas: see the commit message.

Tests (`tests/audio_scratch_test.cpp`): a steady slow hand (one count every 14 blocks) has no silent block and no stopped rate between counts after the second count; a hand at 1x stays within 15 % of rate 1 and a held hand ends in exact silence; a reversal of a steady hand falls from the first count back and ends below -0.7; the AA is bit-exact against aa off at |rate| <= 1 and takes a 15 kHz tone at rate above 3 below half its level; `set_tuning` defaults, clamps and NaN. The mirror of TAPE STOP and the A/B scenarios were retuned (settle lengths for 70 ms, the 32 gate) and the goldens re-pinned. CPU: not measured (host only); the check is on the unit, QA-PRF-150 with SCR on, a fast turn (the AA runs one pole a frame) and still.
