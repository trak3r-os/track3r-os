# OS-CECHECK — what tracker-ce settles for the file formats, the MIDI sync and the defaults

Status: specified 2026-11-06 (drafted by an agent; Q1 decided by the maintainer 2026-11-06: option a, OS-VOLLAW2; Q2 to Q5 open), not implemented · Level A for K1, K2, K4, K5 (documents and pinned tests, no behaviour), Level B for K3 (host tests that may open OS-BUG rows); every later change that a finding asks for is its own row and its own Level (the mixer law is Level C) · Backlog row OS-CECHECK ("Check against tracker-ce", approved by the maintainer 2026-11-05; `docs/roadmap/BACKLOG.md:123`) with the three IDEA rows folded into it on 2026-11-05 (OS-VOLLAW, OS-AMPATK0, OS-WTLFO-DEFAULT: `BACKLOG.md:208-210`) · Facts from `dev` at c875105e and from `polyend/tracker-ce` at 7fd6c2c (cited `tracker-ce@7fd6c2c:<path>:<line>`; a read-only clone, `build-ce/tracker-ce`, untracked, 10 commits deep, so there is no history to blame a fix with) · What tracker-ce shows is **verified (tracker-ce)**, which CLAUDE.md counts as evidence of the official firmware; whether the shipped official firmware 1.9.x equals tracker-ce@7fd6c2c in these places is an **open research question** (no unit comparison is planned).

The row has three parts and this spec answers most of them from the source alone, which is why it can be cheap: (a) the file versions, (b) the MIDI fixes, (c) the defaults and laws. Section 2 holds the facts, section 3 the verdict for each check, section 4 the slices. Nothing in this spec changes the sound, a file or a screen.

## 1. Goal

Settle, against the published official source, every "does the official firmware do this?" question of the row, and turn each answer into one of: a pinned test or a doc line (nothing to fix), an `OS-BUG-*` or parity row with a recommended default (something to decide), or a unit/host check that only a person can run. No behaviour of this OS changes in this spec.

## 5. Assumptions (decided here; each local, testable and reversible)

- A-1 Nothing in K1-K5 changes a file the OS writes or a sound it makes; every behaviour change is a separate row with its own Level.
- A-2 tracker-ce is read as the official firmware (CLAUDE.md), with the open question of section 7 recorded once instead of on every row.
- A-3 The dB figures of F9 are computed by taking 20 log10 of the table entries; they are the gains the code multiplies, which is what a listener hears. The 10 log comment of F12 is not applied to them.
- A-4 The padding of the project header (F2) is computed from the struct alignment; a real file settles it (K1b).
- A-5 A proposed row text (K2) is a draft for the maintainer; nothing is written into `docs/roadmap/BACKLOG.md` by this spec.
