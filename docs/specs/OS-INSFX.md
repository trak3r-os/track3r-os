# OS-INSFX: effect modules (.tmod kind 2) as per-track inserts and a master insert

Status: design only (phase 1), amended 2026-11-01 with the risk review's findings (section 12) · Level C (the audio path, a published module ABI that is used for the first time by this item, and a persistent-format change) · Row `OS-INSFX` of `docs/roadmap/BACKLOG.md`, approved by the maintainer 2026-10-31 · No code in this phase.

Classification: all of it is **new Community OS behaviour** (proposed 2026-10-19 at the maintainer's request). No claim of parity: whether the official firmware has inserts, and what they would do, is an **open research question (Q)** that this item does not need.

## 0. What exists (read from the tree, 2026-11-01)

- `Graph::Strip::insert[2]` (`audio/include/o3os/audio/graph.h`, `Insert{fn, state, bypass}`; `Graph::install_insert`, `set_insert_bypass`, `audio/src/graph.cpp:135`). The call is in the strip loop (`graph.cpp:893`): after the source block is a mono Q15 block, in place, **before the sends and the fader**, `InsertFn = void(*)(void* state, int16_t* io, uint32_t n)`. Installing leaves a slot bypassed. **No production code installs an insert**: only `tests/audio_graph_test.cpp:857` and `tests/audio_stereo_test.cpp:569`. The slots are written by plain stores, so they are legal only "before start or with the render stopped".
- `Graph::side_pass` (`graph.cpp:953`) gives the stereo side S of a stereo voice no pass while an insert is in the path ("an insert processed M only"). So an insert makes a stereo track mono (section 4).
- The master chain `kMasterChain` (`Headroom, Saturation, Eq, Bass, Limiter, Space, BitDepth`) is float planes L and R, `MasterFn(state, float* l, float* r, n)`, `StageSlot{fn, state, bypass}`.
- Effect modules: the ABI accepts kind 2 (`image.cpp:165`, `loader.cpp:123`): one mono float input, one mono float output, `in` and `out` may be the same buffer, `render` returns 1 while a tail may sound and 0 when silent and idle, views are allowed for any kind (ABI 1.1). `modules/templates/effect/` builds. **This OS has no effect slot**: `ModuleBinder::bind_next` refuses a non-instrument (`WrongKind`), `module/sdk/README.md` sections 0 and 10 say design-only.
- The CPU governor (`audio/module_governor.h`) measures each instance with the cycle counter, admits a note that would start a voice, and mutes an instance over 50 % of a block for 4 blocks. It is note-oriented; a continuous insert needs the same estimator with a different admission (section 6).
- `ModuleVoices` has the main-loop to render protocol this item reuses: a bounded SPSC command ring drained at block start, `retire_all` / `quiescent` (two block starts) before `shutdown()`, bump arenas with no free (`ModuleSet::take_state`, mark and rollback only).
- Project format: IFF chunks, unknown chunks kept (at most 16, 16 KiB pool) and written back; `MODR` holds at most 16 module references and `add_module` only appends; `LRNB` is read tolerantly (an entry for an id this version does not have is skipped and counted); mixer edits are not journalled by undo (`model/undo.h`, D10).

## 1. Intent and architecture

An effect `.tmod` from `/modules/effects/` can be placed in `INS A` or `INS B` of any of the 16 tracks, and one on the master (dual mono). The user picks it, edits its generated parameters, binds MIDI Learn to them, toggles bypass, and the project stores it. A module load or unload never runs in the audio callback; the engine never allocates; a heavy or faulty effect degrades to **dry** (a passthrough), never to an underrun or silence.

```
main loop:  picker / project load -> ModuleSet load (sliced) -> InsertHost::bind (init(), params) -> command ring
render:     Engine block start: InsertHost::begin_block(graph)   [drains commands, installs / removes into the Graph]
            strip: source Q15 -> INS A -> INS B -> sends -> fader -> pan          (existing position)
            master: Headroom, Saturation, Eq, Bass, [INSERT], Limiter, Space, BitDepth
```

One new class, `audio::InsertHost` (`audio/include/o3os/audio/insert_host.h`, `audio/src/insert_host.cpp`), all in flash (`O3OS_AUDIO_COLD`: at most 4 instances run per block, so a long call each is below noise), sharing with `ModuleVoices` the cycle counter, the enter/leave hooks and the `gov::Governor` (accessor). It is not a second `ModuleVoices` mode: an insert has no note, no track block of its own and no slab output block.

### 1.1 The float / Q15 adapter (per-track insert)

`InsertHost::run` is the `InsertFn` the Graph already calls, `state` = the host's instance record:

1. (Idle effect: when the last `render` returned 0 and the input block is all zero, the host skips steps 1 to 3 and the effect is not called; the scan is a word-wide OR over the 64 samples.) `kernel::q15_to_float(fl, io, n)` (exact, `/32768`) into one 64-float scratch block (the graph's `fl_[0]` is free at this point of the strip loop; the host owns no extra block).
2. `entry.render(state, fl, fl, n)` in place, between the platform's enter/leave stamps (fault attribution, as for instruments), `n` is 64 (the module must accept 1..64, ABI).
3. Back to Q15 with the **module rule** (`to_q15` of `module_voices.cpp`: `VCVT` fixed point, truncate toward zero, `SSAT` 16, **NaN gives 0**), moved unchanged to a shared header `audio/module_q15.h`. Not `kernel::float_to_q15`: that one maps NaN to +32767, a DC rail from a faulty effect. Saturated samples are counted (`Stats::saturated`, shown on the page).
4. A transition block (bind, bypass on or off, forced bypass, slot clear) mixes dry and wet with a 64-sample linear ramp (section 3), once, about 0.4k cycles. On the same transition the stereo S of a stereo voice (dropped while the insert is in the path, section 4) is restored **through a one-block ramp** (0 to 1 over the block, 1 to 0 on the way in), never as a step; the ramp is one `gain_pan_st` with a ramped level in the strip loop's existing side pass, no new per-block code in SRAM_L.

Cost [est, not measured: from the instruction count of the two loops and `k_q15_to_float`, `k_float_to_q15` bench rows, to be replaced by the unit's `diag bench insert`, rows `insert_effect`, `insert_ramp`, `insert`: the adapter is `insert` minus `insert_effect`]: conversion in about 3 to 4 cycles a sample, out about 8 (the module rule's `to_q15` has the `SSAT` and the clip compare that counts saturated samples), call, stamps and checks about 120, the silent-input scan (32 word loads and an OR, only when the effect last returned 0) about 0.1k: **about 1.2k cycles a block, 0.46 % of the 261,225-cycle block, per active track insert**, before the effect's own render. Four inserts: about 1.8 %. A biquad effect is about 12 cycles a sample [est] (0.3 %); a delay with interpolation about 0.5 %; a reverb would be several points and falls under the effect budget (section 6). The master insert has no conversion (the planes are float; the host scrubs NaN and infinity with a compare a sample, about 0.4k) and runs two instances: about 0.2 % plus twice the effect.

State and code: an instance's state comes from the module state arena (SRAM_U, 4 KiB, about 640 B left after eight instruments) and then SDRAM at about 28 cycles an access (`cpu-budget.md` section 2): an effect aims at a state block of 512 B or less; a delay buffer lives in SDRAM and is read sequentially. Hot code of all loaded modules shares the 14 KiB SRAM_L slab (about 8 KiB used): an effect aims at 2.5 KB of hot code (`tmod-perf` section 4). Several inserts of one module share one load and have one instance each (`state_bytes` each).

## 2. Where it sits in the graph

- Track: the existing slot position, unchanged: INS A then INS B, on the track's mono block, **before the sends and the fader, in both SENDS modes**. The fader and pan law therefore follow the insert; the sends hear the processed signal. The input strip (16) and the audition strip have no insert.
- Master: a new `MasterStage::Insert` between `Bass` and `Limiter` (so the limiter catches what an effect adds, the reason the DJ stages sit there, OS-DJ), `kMasterChain` row `{Insert, "insert", 0}`. It runs through the existing `StageSlot` / `MasterFn` (float planes), two instances (L and R) fed the same parameters. `kMasterStages` becomes 8; the table is the single source of order (a test holds the enum and the table equal).
- The tracker FX, the Perform layer and the sampler voices are untouched.

## 3. RT rules and the hand-over of a swap

Render context rules (all of `run`, `begin_block`, the parameter hook): no allocation, no SD or file I/O, no blocking, no printf, no virtual call, no libm, no `double`, bounded loops (instances <= 4, commands <= 32 a block). Module code is called only from the render context; `init()` and `shutdown()` only from the main loop. **Module load, `init()`, `shutdown()` and the memory they use never run in the audio callback.**

Single-writer protocol (documented at the declarations):

- The Graph's insert slots are written **only by the render context**, from `InsertHost::begin_block`, at a block start. The main loop never calls `install_insert` after the audio started (so the "stopped render" restriction of its comment holds). No slot is torn, no pointer is read while it changes.
- **`begin_block` runs every block, whether or not the strip loop reaches the insert.** A slot that is ramping out is retired (bypassed, cleared, the block count stored) by `begin_block` itself, never by `run()`: a strip that went idle after a `Deactivate` is never run again, and a retire that waited for `run()` would never come (`quiescent` would never be reached and the module could never be shut down). `run()` only does the ramp arithmetic of the block it is called in. The call is placed in an existing flash call of the block start (not a new call in SRAM_L code, section 5 S1).
- **Generation.** Every binding (an instance record handed to a slot) carries a 16-bit generation, incremented at each `Activate`. `Activate`, `Deactivate`, `Bypass` and `ParamChange{ParamKind::Insert}` name the instance and its generation. The render applies a `ParamChange{Insert}` only when the slot is active **and** the generation in the change matches the binding's; otherwise the change is dropped (a stale change queued for a binding that was unbound and whose instance was reused by a new bind never reaches the new module's `set_param`). The editor holds the generation of the binding it edits.
- **A full command ring never drops an Activate or a Deactivate.** `bind` / `unbind` / `bypass` return `Retry` when the SPSC ring has no room; the main loop keeps the request and pushes it again on its next tick (the picker and the console show nothing different). Only `ParamChange` may be coalesced or dropped (the newest value of a parameter wins).
- **Bind (main loop).** The module is loaded by the sliced loader (as the instruments are); `bind()` takes the state block, calls `init()`, applies the stored parameter blob (a short blob sets the first parameters, non-finite values skipped, as `ModuleVoices::bind`), then pushes `Activate{instance, track, slot}` into the SPSC command ring (release). At the next block start the render installs `run` with the instance and un-bypasses it, starting at the dry/wet ramp "in" (a fade over the first block).
- **Unbind and bypass (main loop).** `Deactivate` and `Bypass{on}` are commands. The render ramps the wet signal out over one block, then bypasses and clears the slot (`install_insert(t, s, nullptr, nullptr)`) and stores the block count it did so (release). The main loop sees `retired(instance)` and `quiescent()` (the render has passed two block starts since) and only then calls `shutdown()`; the memory is **not freed** (bump arena): the instance goes on a per-module free list and the next bind of the same module reuses it (`shutdown`, zero, `init` again; the generation moves on). A different module takes new arena room; with none left the picker says `NO ROOM, RELOAD THE PROJECT`, as the instrument picker does. A project load retires all (`retire_all`, wired to `ModuleVoices::retire_all`) and rolls the arenas back.
- **Parameters.** An edit is a `ParamChange{ParamKind::Insert, index, field = parameter, value}` through the existing 256-entry ring, drained in the graph's pass; `Graph::apply` routes the kind to an installed hook (like `inst_hook_`) that calls `set_param` of the instance, in the render context (what the ABI requires). No second ring. The OS does not clamp (the module does: ABI). The stored blob (model) is the main loop's copy and is written by the editor, never read by the render.
- **State reset (no ABI change).** The ABI has no reset call, so a reset of an effect's state is `shutdown()` + `init()` on the same state block, **run on the main loop through the swap protocol** (Deactivate, wait for `retired` and `quiescent`, `shutdown`, zero, `init`, re-apply the parameter blob, Activate; the render never sees a half-reset instance). It happens (a) when the user un-bypasses an insert (the wet state restarts from silence, not from whatever the effect held when it was bypassed; a bypassed effect is not run, so its state is old) and (b) at the **start of an export**, for every active insert, so that two exports of one song give the same bits (the export does not begin until each reset has finished and the inserts are active again; a few block times). Transport stop does **not** reset: tails ring out and are kept (**new Community OS behaviour**).
- **Export (offline render).** Admission and both safety nets are off in an export (as for instruments, OS-WAVEXP), so two passes give the same bits; the state reset above runs before the first block of the export.
- A tail: section 5, slice 2.

## 4. Behaviour rules

- Track insert: mono. A stereo-voice track with an un-bypassed insert plays its M only (existing behaviour of `side_pass`; the S is dropped), noted in the manual and the QA row. Bypassing restores S, through a one-block ramp (section 1.1 step 4), as does clearing a slot.
- Master insert: dual mono (L and R each get an instance with the same parameters). No stereo effects in this item.
- Latency: an effect adds none by contract (the ABI has no latency report); a lookahead effect would move one track against the others, so none is shipped.
- Idle and tail: `render` returning 0 with a silent input means the effect is idle; the host skips it until the input is not silent again (a skipped idle effect costs the scan only). A tail past the end of the source is slice 2. Transport stop keeps tails (new Community OS behaviour); only un-bypass and the start of an export reset the state (section 3).
- Bypass is a host state (a ramp), not the module's own `Bypass` parameter (the template has one; both may exist).

**S2 fold (delay gaps; new Community OS behaviour, decision of the orchestrator).** The first zero rule (32 blocks, 46 ms, of exact zero output) cut a 300 ms delay's echo, any pre-delayed or 100 % wet effect, and left the frozen delay line to replay a stale echo on the next note. Now `zero` counts only blocks whose source is silent (`silent_in`) and is reset by every block with a live source, so the zeros of a pre-delay while playing never count; the threshold is `kTailZeroBlocks` = 2 s (derived from the engine's rate like `kTailMaxBlocks`, `std::uint16_t` now); the 10 s cap stays. A module that always returns 1 (a gain or a filter) now keeps its strip live for 2 s after every stop (46 ms before the fold): a CPU cost only, read with `diag cpu` in the S2 unit check. Limits, stated: a ring that needs more than 2 s of exact silence between two echoes, or that rings longer than 10 s, is cut; a cut ring may leave state in the module (a delay line that still holds signal) that plays on the next note. `Graph::set_insert_tail` (flash) also writes `tail` only when the slot holds a module (`fn != nullptr`), so a render that writes the byte after a forced release (`release_all`) cleared the slot is ignored in most cases; a window of a few instructions remains (the render past the check when the clear lands), and a byte set there keeps the strip live on the zero block, CPU only and no audio, until the slot is bound again or bypassed. (A check in `run_tracks`' tail branch cost +20 B of `.ramfunc_l`, over the S2 cap of +32 B, so it sits in the flash setter.) Tests (`audio_insert_test.cpp` `tail:`): an echo after 300 ms of zeros, twice; a tail byte on an empty slot is ignored; a wet-only pre-delay stopped before its copy arrives; a source restarting while the ring is audible; two slots with one in a tail; slot A's tail through slot B.

## 6. Cap and CPU guard

- **Cap: 4 effect instances active at once** (a master insert is 2). Technical reasons: the module state arena (about 640 B free), the 14 KiB hot slab (about 6 KiB free), and the CPU the heavy songs have left (Dense8 about 49 %, the stress song about 90 % [unit, `cpu-budget.md`]). A fifth assign is refused (`INSERTS FULL`); a project file with more records is read as far as the cap and the rest counted as skipped. The constant lives in `audio/module_governor.h` next to the others and is lowered or raised only from the unit measurement of S8.
- **Effect budget** (`tmod-perf` section 1, "an effect gives its cost per instance"): a track insert aims at 3 points or less and a master insert (two instances) at 6; going above needs the maintainer's agreement.
- **Reuse of the governor.** The estimator type (`InstanceGov`: min of two blocks, moving max with the 370 ms decay) is reused for the figures `InsertHost` keeps, but **`InsertHost` does not call `Governor::account` and does not feed `observe_block`'s per-instance net**: the insert cycles stay in `base` (the render's block total minus the module voices), so the instrument governor's note admission sees them without a change. `InsertHost` measures each instance's cycles itself (the DWT counter around its own `run`, 2 reads a call) for its own nets and for `diag ins`. Admission differs from a note's because an insert has no note: **at activation** (assign, un-bypass) `InsertHost::admit` accepts when `the mean of the other work + the running inserts + cost <= threshold (90 %)` and the inserts together fit the instance budget (the next two bullets), `cost` being the module's measured figure, or, while unmeasured, 0 at a first bind (the nets judge it once it runs, see the admission bullet) and `kColdInsertPercent` (10 %) at an un-bypass; otherwise the insert stays bypassed and the page says `NO CPU`. At a project load the inserts are admitted without the check (the instruments are bound first and the render is the judge) and the aggregate net acts. Two nets, both **force bypass** (a one-block ramp to dry; flagged `OVER BUDGET` with a strip message; cleared by the user toggling bypass or by a reload), never silence: (1) the **per-instance net**: an instance over 50 % of a block for 4 blocks (the instruments' rule, on the host's own measurement); (2) the **aggregate net**: if the sum of the active inserts' cycles stays over the insert budget (the 90 % threshold less the mean of the other work without inserts, evaluated from the host's own sums; see the next bullet) for N blocks (N = 4, the same constant as the per-instance net), the **most expensive active insert** is force-bypassed to dry, and the check repeats on the following blocks until the total is under budget. A bypassed insert is not run and so is not measured: the figure shown for it is its last one. At a project load every insert is admitted and the aggregate net is the judge. `base` contains the inserts' cycles, as said above.
- **The aggregate net and admission judge the mean of the other work, not `base` (S2 unit regression, 2026-11-01; fold of the CPU-net review; new Community OS behaviour).** `base` is a moving max, so on a busy project that plays without underruns (Dense8: render mean about 86 %, peaks past 100 %) it sits over the 90 % threshold, the allowance `threshold - others` was 0 and a 1.3 % insert was forced to dry after 4 blocks (a light project, peaks near 50 %, never saw it). Both now take `others` from `InsertHost`: all the render's cycles but the inserts', the instrument-module voices' included (`Governor::last_total()` less the inserts' own measured cycles of that block; decision of the orchestrator, 2026-11-01: heavy module voices leave room for fewer inserts; the instruments' own note admission is unchanged) as two moving means, a slow one (1/256 a block, the base's rate of fall) and a fast one (1/32), and `others` is `max(slow, fast - 5 % of a block)`. The slow mean alone followed a light render that turned heavy (inserts loaded unchecked at a project load, then 30 % -> 70 % with 40 % of inserts) only after about 110 blocks, all over 100 %; the fast one acts in about 35. A mean that rises fast and falls slowly was tried on paper and rejected: it climbs on spikes (Dense8's pattern settles near 106 %), so the fast mean is symmetric and the deadband keeps its ripple (a few percent) out of the judgement. Both start as plain running averages of their first blocks (divisor = the block count, up to 32 and 256), the first block seeded at the threshold at most, so one cold block at boot (150 %) is forgotten at once; they are kept across an export (the nets are off in it, the means are not followed, and a reseed from one cold block could force an insert that was on). An insert is forced only when the inserts push that mean over the threshold, or past the instance budget. The inserts' cycles are measured, not subtracted from a peak, so no `gone` figure is kept.
- **Admission is the aggregate net asked in advance (as built, fold of the CPU-net review).** `InsertHost::admit` (bind, un-bypass) accepts when `others` + the estimates of the inserts that run (or will, once the render takes them: bound, not bypassed, not forced) + the candidate's estimate stays `<= threshold` and the candidate and the running inserts together stay `<= the instance budget`: the same input and rule as the aggregate net, so a bind is admitted exactly when the net would not force it (Dense8: a 1.3 % insert is admitted, a 15 % one is refused). The candidate's estimate is its measured figure when the record held the module before. **A first bind of a module that has no measured figure counts the candidate as 0** (decision of the orchestrator, 2026-11-01; the same principle as "admit at project load and let the aggregate net act"): it is admitted when `others` + the running inserts' estimates leave room under the threshold and the budget, then measured, and the per-instance and aggregate nets force it to dry if it overloads (Dense8: admitted; a render whose other work is itself over the threshold: refused). An un-bypass keeps the cold assumption (`kColdInsertPercent`, 10 %, an unmeasured effect is not trusted to be cheap) when it has no figure, so an over-budget un-bypass needs force. The inserts that stopped are not in the sum (their estimate is not counted unless they run), so a re-bind right after an unbind is not refused for its own old cycles. The module voices are in both the net and admission (`others` is every render work but the inserts: with module voices at 30 % and other work at 55 %, a 10 % insert is forced; with no module voices it stays on).
- **The aggregate never exceeds the instance budget (new Community OS behaviour).** The aggregate allowance is `min(threshold - others, budget)`, so the active inserts together may take at most the instance budget (50 % of a block) however much room the threshold leaves, and less when the other work leaves less than that.
- Both nets and the admission are off in an export, as the instruments' governor is. `diag ins` prints the figures; `diag cpu` is unchanged.

## 7. Persistent format: `INSX`, version 1.0 (additive)

No existing chunk changes: no byte of `PHDR`, `MODR`, `INST`, `MIXR`, `LRNB` moves, and a project that **never had an insert** is **the file it was** (the optional-chunk precedent of `MIXR`, `SNFX`, `LAW `). `MODR` is not pruned (`add_module` only appends): a project whose insert was removed keeps the effect module's `MODR` entry and so differs from the file that never had one. That is documented in `docs/formats/o3-project.md` and not changed. One new known chunk, id `INSX`, version `0x0100`, written only when the project has an insert, **after `LAW ` and before `CRC `**. In `formats/src/native_reader.cpp` `INSX` takes a **new rank after `LAW `** (`kRankMidi + 10` = 19) and the **`CRC ` rank is bumped** (`kRankCrc` 19 to 20, updating its comment); the writer emits it in the same place. An older reader sees it as an unknown chunk anywhere after `PHDR`.

```
INSX payload (big-endian, like every chunk)
u16 version = 0x0100
u8  count                 0..4 records (the cap)
record x count, ascending (where, slot), no duplicates:
  u8  where               0..15 track index, 16 master
  u8  slot                0 or 1 for a track, 0 for the master
  u8  module              index into MODR (the module's name and ABI are there)
  u8  flags               bit 0 bypassed; the other bits 0
  u8  n                   parameter count 0..32 (O3M_PARAMS_MAX)
  f32 param[n]            the module's parameter blob in its order (finite), BE
(a later minor appends AFTER the last record; a reader of 1.0 ignores the rest)
```

Size: `3 + sum(5 + 4n)`, at most `3 + 4 x 133` = 535 bytes. Model cost: `InsertState` of 4 records, about 540 B in the model arena (SDRAM, `kModelArenaBytes` +540 and its `static_assert`).

- **The module names are in `MODR`.** The writer adds an insert's module to `MODR` (`add_module`; the existing rule: at most 16 modules in all, unique names, ABI major and minor). The cap of 16 is shared with the instrument modules; a full table makes the assign refuse (`NO ROOM`). `MODR` is never pruned (`add_module` only appends), so the indices in `INSX` stay valid.
- **Loader, this version.** No chunk: no inserts, and the inserts of a previously open project are cleared (the MIXR rule). Chunk 1.0: exact bounds; `count` above the cap or a record that does not fit is `Malformed` for the *structure*; **a record whose module index is past `MODR`, whose `where` or `slot` is out of range, whose `n` is above 32, or with a non-finite parameter is skipped and counted** (`Report::settings_skipped`, the LRNB rule: the project still opens). Newer minor (1.x): at least the 1.0 minimum, records read as far as 1.0 knows, the rest skipped, `newer_minor` set (the appended data is lost on the next save, as for every chunk). Newer major: `NewerMajor`, as for every chunk.
- **Writer.** The smallest form: the chunk only when at least one record exists; the records sorted.
- **Old firmware, new file.** It reads `INSX` as an unknown chunk, keeps it (one of 16, 535 bytes at most of the 16 KiB pool; `OGPN` can fill the pool, then it is dropped and counted as any unknown chunk) and writes it back unchanged. The project **plays without the inserts** (the sound differs; the file is not refused). The `MODR` entry for an effect module does **not** make the old firmware load it: `ModuleBinder::wanted` (`app/src/module_binder.cpp`) loads only a module that a Module instrument names, so an effect that only an insert names is never loaded (no arena use). An old firmware that saves the project keeps the chunk and the `MODR` entry. A **Learn binding of an insert parameter** in `LRNB` (S7) is skipped by an old reader and lost on its next save (accepted, the tolerant rule). Python reference and `docs/formats/o3-project.md` get the new section in S3.
- **Format decision** (D2): additive optional chunk, no version bump of an existing chunk. A loader for "the old version" is the absence of the chunk. **D2 decided by the maintainer on 2026-11-01: the new optional chunk `INSX` 1.0, after `LAW `, written only when used.** (S1 and S2 write nothing to disk.)

## 8. ABI

**No change is needed: kind 2 and ABI 1.10 are enough for slices 1 to 8, state reset included**: the ABI has no reset entry, so the host resets an effect by `shutdown()` + `init()` on the main loop (section 3), never by a new call. The descriptor, `render(in, out, frames 1..64)`, `set_param`, the parameter flags, views (any kind) and the return value for tails are all used as published. `O3M_ABI_MINOR` stays 10 and `module_image_test.cpp`'s layout test is untouched. What is missing and is **not** done here (each is an additive ABI minor if the maintainer wants it later): tempo and transport for tempo-synced effects (`o3m_host` has no tempo for effects; `get_tempo` is in the app-only io table), a stereo effect (two inputs, two outputs), a latency report, `note_on` for a gated effect. The SDK README and `module/CLAUDE.md` lose the "design-only" sentences in S8; they must say that an effect gets `n` of 1 to 64 and **must return 0 when idle**.

## 10. Risks

1. **CPU.** The stress song is near 90 % and the governor threshold is 90 %. Inserts add the adapter (about 0.3 % each) and the effect; the cap, the admission, the forced bypass and the per-module measurement are the controls. A reverb-class effect would not fit the budget on a dense song: it needs the maintainer's agreement and a measured figure.
2. **SRAM_L headroom** (176 B at the last recording in `audio/CLAUDE.md`): S1 targets +0 B (the parameter route through `param_hook_` and `begin_block` from a flash call); S2 may cost up to 32 B. Any growth in S1 stops it for a decision.
3. **State in SDRAM.** The 4 KiB state arena is almost full; an effect state beyond it is read at about 28 cycles an access. Mitigation: the 512 B target and the measurement in S8; a dedicated insert arena is the fallback (D11).
4. **No unbind frees memory.** The arenas are bump arenas; swaps of different modules consume room until the project is reloaded. The free list bounds same-module swaps.
5. **Faulty or hanging effect** in the render context: the same exposure as an instrument (the crash record names the module through `fault_id`; no watchdog, README section 10), but an effect sits in the path of a whole track or the master. NaN and infinity are scrubbed, overload degrades to dry (per instance and in total), an infinite loop is not contained.
6. **Stereo.** A track insert drops the side of a stereo voice (existing behaviour of `side_pass`); the master insert is dual mono, so a stereo-width effect is impossible. Both are told to the user.
7. **Old firmware** plays a project with inserts without them (the chunk and its `MODR` entry are kept, the effect module is not loaded), and loses insert Learn bindings on its next save.
8. **`MODR` shares 16 slots** with the instrument modules.
9. **Project load order.** The inserts bind after the instruments, so the first blocks of a loaded project play dry for a few hundred milliseconds, then fade in (accepted; the same as an instrument module that is still loading).
10. **Master chain renumbering.** Adding `MasterStage::Insert` mid-chain moves the slot numbers of `Limiter`, `Space` and `BitDepth`; no persistent file stores them (check in S6 with a grep of the settings and project formats), tests and `diag` print names.
11. **Hardware.** Nothing here is verified on a unit: the adapter cost, the effect costs, the click-freeness of the ramps by ear, the tail and the master insert are each a named unit check above.
