## 1. Goal

An instrument slot (amp, pan, cutoff, wavetable position, granular position, finetune, and the new granular length) can be a **WT Env** (a 128-point contour played over a duration, one-shot or with a sustain point, with time and level warps) or a **WT LFO** (the same contour looped at the LFO's tempo-synced rate), as in tracker-ce; the step FX w (WT Amp Env), y (WT Filter Env) and z (Granular Length) play as in tracker-ce; files keep every byte tracker-ce stores.

## 3. Design

### 3.1 What must land first

- **OS-CEFXIDS (OS-CEPAT S0) before W6a and W6b.** Without it OG 43, 44, 45 are our core FX 43 Speed, 44 Tempo fine, 45 Order jump (F18); W6 implements model ids 96, 97, 98.
- **OS-CEPAT S1 (the v6 pattern reader) before W6 has anything to play from a real file:** tracker-ce writes w, y and z only into v6 patterns, which fail to load today. W6's tests use synthetic model patterns, so S1 gates the fixture test only.
- **Nothing gates W1 to W5 and W7a:** v9 instruments with WT slots load today (F16).
- **INST minor:** OS-CEPLAYTHRU P1 and W1 each append to INST; the first to merge takes 1.6, the other 1.7 (append-only rule).
- **Q1 answered before W2** (the component's approval). OS-CECHECK (a) (a tracker-ce-saved instrument) confirms the WT bytes on a real file; OS-CECHECK (c) (whether a new wavetable instrument enables the position LFO, ex OS-WTLFO-DEFAULT) is related and not in scope.

### 3.2 Data (W1)

- Model `Lfo` gets `wt_bend` and `wt_sust` in its two padding bytes (struct sizes unchanged). For a slot with loop 2 or 3, `shape` is the contour index 0..255.
- OG read: for loop >= 2, shape verbatim and bytes +2/+3 read; for loop <= 1, today's rule (above 4: Triangle). OG write (Export): Q4 a, a new `ExportDrops::wt_mod` counter; the Sine rule (`lfo_sine`) applies only to loop <= 1.
- Native: INST minor 1.7 (or 1.6, 3.1) appends 12 B, `wt_bend` and `wt_sust` of the six slots, written only when a slot has loop >= 2 or a non-zero byte. Reader: shape verbatim when loop >= 2 in a chunk of that minor; in an older chunk loop >= 2 reads as 1 (an LFO: what those files played, A3). `tools/o3project.py` and `docs/formats/o3-project.md` follow; `docs/formats/og.md` section 5 gets the bytes.

### 3.3 Contour bank and evaluator (W2)

`audio/include/o3os/audio/wt_contour.h`, `audio/src/wt_contour.cpp` (pure; with Q1 a, the port of the component, notice in `THIRD_PARTY.md`): a bank of 256 x 128 int16 in the SDRAM arena (64 KiB) and a pointer table (1 KiB); `wt_make(shape)` makes one contour in the main loop (about 40k cycles [est]; all 256 about 55 ms [est]) and marks it; `wt_eval(shape_ptr, phase, bend)` (float, F4) for every destination. The main loop makes the contour before it stages a descriptor that names it (`make_sample_desc`), so the render never reads an unmade one. The evaluator stays in flash (SRAM_L has 864 B left).

### 3.4 Non-amp modulators (W3a, W3b)

- `FilterMod` gets kinds `kFmodWtEnv` (3) and `kFmodWtLfo` (4), and `wt_bend`, `wt_sust` in its tail padding (`sizeof` unchanged); `make_sample_desc` maps loop 2 and 3 to them, with `shape` the contour.
- `ModGen` runs them without growing (static_assert 44 B): WT Env uses `stage`, `key`, `e_t` (samples into the stage), `l_inv` (1 / duration), `e_max` (the release's start phase), `e_out`; WT LFO uses the LFO's `l_period`, `l_shift`, `l_inv`. Laws F5 and F6 (verified parity).
- W3a: the cutoff (every 16 samples, `filter_run`); W3b: pan, finetune and wavetable position (once a block, `mod_block`), and slot 3 honours bit 0x01 for the position (F2: fixes F16's second case).
- Known difference (new Community OS behaviour): a Filter LFO FX switched on over a running WT LFO only re-rates it (the contour keeps playing), while a new note plays the triangle.

- **W3c (Q3 a, after the W3b unit run: +4.58 points over the ADSR control, limit 3).** (1) A slot's warps are applied once, when the descriptor is made (main loop, `make_sample_desc`): `audio::wt_bake(shape, bend)` evaluates the contour at the warps at the contour's own 128 points into a pool of 128 baked contours (33,028 B in the reverb region's spare tail, `mem_map.h` `kWtBakeBase`), deduplicated by the canonical (shape, warp X, warp Y), and returns an id (1..128) that the slot keeps in `FilterMod::delay` (unused by a WT kind; a live SOURCE or enable edit that takes the slot off WT clears it, `leave_wt`); the render evaluates the baked contour with no warp, so the two divisions are gone (`wt_eval_slot`, which trusts an id only up to the entries made). Id 0 (no warp, the pool full or unbound) applies the warps live as in W3b, so the sound is right whatever the pool holds. The baked table is the composite resampled at 128 points: **new Community OS behaviour**: over the 256 contours and 5 x 5 warps the mean difference from the live evaluation is 0.54 % of full scale and the 99th percentile 0.14; a contour that jumps moves the jump by up to one baked interval (full scale there): with warp X +7 on the stepped groups (3, 6, 7, 9, 14) the mean is 1.3 % and 3.4 % of the phase points are more than 0.1 off. The pool is emptied at the project load (`wt_bake_reset`, after the voices' table is cleared and the voices are quiet: the Settle phase); between two loads a long sweep of a WT shape or warp can fill it, the slot then plays live (correct, slower) and `diag cpu` shows `wtbake used/128 refused n` (refused counts calls: a rebuild counts once a slot). (2) The cutoff's WT kinds are evaluated when 64 or more filter samples have gone by since the last evaluation, on `filter_run`'s 16-sample grid (`wt_cut_eval`; the grid points in between hand back the last output), as pan, finetune and position are once a block: for a note that starts at a block's start that is once a block, at its first sample; a note that starts mid-block gets its first re-evaluation 64 to 79 samples after its start, a NoteOff reaches a WT Env's release at the next evaluation (up to 79 samples late), and a WT Env with a decay under about 10 ms gets only a few cutoff points. The cutoff coefficient steps every 64 samples (1.45 ms) for a WT slot; the ADSR and LFO kinds keep the 16-sample grid. (3) The step FX w and y (W6a) are not part of W3c: how a warp offset reaches the render is W6a's to decide (Q3 chose a, the warps in the render or baked at bind time). Estimate [est]: 36 evaluations a block on the worst arm instead of 72, none with a warp: about +2 points over the ADSR control instead of +4.58.

### 3.5 Amp (W4)

Loop 2 replaces the ADSR (`AmpEnvelope` is not run) and loop 3 the tremolo: both drive the tremolo path's multiplier, evaluated at every 16th sample and walked linearly (`trem_span`), with `mg[kMgTrem]` as the state; laws F7. A one-shot WT Env at its end releases the voice with the usual declick. Control rate: ours every 16 samples walked linearly, tracker-ce stepwise per envelope region: new Community OS behaviour (expected inaudible; listened for in the unit check).

**W4 as built (2026-11-07, branch feat/OS-CEWTENV-W4).** `mod_block` calls `wt_amp_block` (flash, once a block per voice whose amp slot is a WT kind) in place of the LFO's grid; `trem_span` is unchanged. Law F7 as specified: the amp WT Env multiplies the voice by y alone (no amount), a one-shot plays to its end whatever the key does and then the voice stops after the multiplier's 16-sample walk to 0 (the declick; `wt_amp_block` calls `stop_voice`); a sustained one holds at the sustain % while the key is held and a NoteOff runs its own release. **NoteOff and `release_all()` (Stop) do not cut a one-shot amp WT Env** — `release_voice` leaves the voice to the WT Env (law F7, verified parity tracker-ce@7fd6c2c:core/libs/Audio/effect_envelope.cpp:472-602); only a NoteFade still fades it (the 300 ms ramp). A gated (muted) track stops the voice at the off stage as well: the gate (OS-ODD11) skips `post_stages`, so `trem_span` never walks the multiplier to 0 there, and `wt_amp_block` also stops on the gate bit — a looped sample with an amp WT Env on a muted track frees its voice slot at the one-shot's end or when its release runs out, without waiting for the unmute. Tests: `audio_voices_test` (the W4 cases, the two gated ones included). **The unit measurements of 3.10 (items 1 to 5) stay open for W4: not run, not claimed here.**

### 3.6 Granular length (W5)

On a granular instrument, slot 3 with bit 0x02 drives the grain length by F12, from any source kind. The state is a sixth `ModGen` per voice kept in an SDRAM array (`O3OS_SDRAM_NOINIT`, 12 x 44 B): it is read once a block, so SRAM_U does not grow (A5). The new length applies at the next grain. Export keeps bit 0x01 only and counts a dropped 0x02 in `wt_mod`.

As built (W5): the block's length is taken at the first grain wrap of a block (one grain rebuild a block a voice, a position move shares it); a source cleared mid-note (live edit, descriptor without the bit) puts `gr_len` back at the grain's next wrap. The storage is raw SDRAM bytes on the unit (a `FilterMod` a sample slot and a sixth `ModGen` a voice, zeroed at boot); a pool with no `grlen_bind` simply has no length destination. The instrument audition (`SampleBank::preview_bind`, `preview_bind_over`) builds a plain, non-granular descriptor, so it has no length source by construction (not a gap). **Open research question:** Export clears bit 0x02 of slot 3's enable byte as `enable & ~2u`, so a non-boolean byte from a foreign file (2, 3, 0xFF) loses that bit; whether the official firmware does the same on such a byte is not established (the code stays as it is: files without the bit are byte-identical).

### 3.7 Step FX (W6a, W6b)

- A second FX info table for model 96..98 (`fx_kind` answers it; 99..127 stay inert); groups `AmpEnvFx`, `FilterEnvFx`, `GranLenFx` appended (26 of 32); voice events through the mod group ids.
- w (96) and y (97): F9 and F10. For y's ADSR case we take the envelope's values (8x, 8y ms; A7). The override lasts while the FX is on the track's rows and is undone at the first row without it (the FX group's existing end rule).
- z (98): F11; fx[0] wins.
- **W6a as built (2026-11-07, feat/OS-CEWTENV-W6a; new Community OS behaviour, the semantics follow the tracker-ce FX 43 and 44 as the spec above states).** The value byte is x (high nibble) and y (low). w on an amp ADSR: attack = T[x], decay = release = T[y], sustain 0 when y <= 6 (T = 0, 5, 12, 25, 45, 80, 140, 240, 400, 650, 1000, 1500, 2200, 3300, 5000, 8000 ms); y on a cutoff ADSR: attack = max(8x, 1) ms, decay = release = 8y ms, sustain 0 when y <= 6; an LFO slot is unchanged. On a WT slot w scales the duration by x (floor 10 ms, ceiling 65535; base 1000 ms when the decay is <= 1) and y shifts the warp X by (y - 8) held to -7..7. The FX is a group (`kModGroupAmpEnv` 23, `kModGroupFilterEnv` 24) that ends at the first row without it. Mechanism: `ifx_event` (flash) keeps the byte, `fxe_apply` (flash) writes a per-voice copy of the slot or the amp ADSR into `FxEnvMem` and sets `Voice::pmask` bit 5 (`kPmFxCut`) or 6 (`kPmFxAmp`); the amp ADSR is a `Voice::env` pointer swap, the cutoff path costs two bit tests in the inline `cut_mod`. A ModSet or ModEnd re-applies to the sounding voice; a live descriptor edit is heard from the next note. The WT Env duration is decided at the note start (the contour reads it at its start); the warp offset is read live, and a slot with an offset other than 0 plays its warps live (the bake id in `delay` drops to 0) because the baked pool is keyed by the descriptor's warps. A WT LFO takes only the warp offset. The Perform LFO on the cutoff wins over the FX. State: `FxEnvMem` is 948 B in SDRAM (`fxe_bind`, `O3OS_SDRAM_NOINIT` in the slack window like `grlen_bind`; a static in the tests and in `o3sim`); it started in SRAM_U (+948 B) and the link failed the 32 KiB floor of ADR 0013 D7 (31,856 B free, the margin before the slice was 36 B), so the copies went to SDRAM. SRAM_U cost, measured on the mk66 linker table against base 3a440b0c: +64 B (139,088 to 139,152 B), which is `FxGroup::kCount` 23 to 25 growing `ControlTable::perf_val_[16][kFxGroupCount]` (int16) inside `Sequencer`, plus `fxe_on_` (4 B) and one `.bss` pointer (inside the same figure; an earlier note of "+4 B" was wrong). The `sizeof(Sequencer)` static_assert at `platform/mk66/src/app_main.cpp:228` keeps about 32 B of margin (96 B before the slice; host x86-64 `sizeof` 9,872 B). ### 3.8 UI (W7a, W7b)

- SOURCE gains WT ENV (3, loop 2) and WT LFO (4, loop 3) (`model/include/o3os/model/params.h:105-107`).
- New virtual fields `0x90 + 5e + f` (`f`: WAVE, DURATION, WARP X, WARP Y, SUSTAIN; 0x90..0xAD), read from and written to the instrument through an action (one undo record, the slot rebinds), not learnable, not in the app SDK.
- Rows: WT ENV: SOURCE, WAVE (F001..U128), DURATION (0..20.000 s, stored in the slot's decay), WARP X, WARP Y (-7..+7), SUSTAIN (OFF, 1..99 %), RELEASE (the existing row), AMOUNT (the existing row): 8 rows. WT LFO: SOURCE, WAVE, SPEED, WARP X, WARP Y, AMOUNT (the LFO's rows): 6 rows.
- W7b: on a granular instrument slot 3 is the GRAN LENGTH destination (bit 0x02), and the MOD page draws the selected contour with its warps (64 points, one FT812 line strip; new Community OS behaviour, the first thing to drop if flash is short). Built, nothing dropped (see "W7b as built").
- **W7a as built (2026-11-07, feat/OS-CEWTENV-W7a; new Community OS behaviour).** SOURCE has five words (Off, Envelope, LFO, WT Env, WT LFO; `kModSources`, `ParamStore::EnvState` maps 3 to loop 2 and 4 to loop 3, the file bytes are the ones W1 already reads, so an instrument that never uses them is unchanged). The five fields `0x90 + 5e + f` are no table row, so `model::param_desc` is null for them and MIDI learn cannot bind them; `app::describe_param` answers them through `model::wt_param_desc`, the reader is `model::wt_param_value` (model layer: the screens and the simulator cannot include `app/src/param_access.h`), the writer is `write_wt_param` (`app/src/param_actions.cpp`: copy the Instrument, edit the byte, `Editor::set_instrument` = one undo record, `request_rebind(slot)`). WAVE is the contour byte `Lfo.shape` (a new `ParamUnit::WtWave` shows `F001..F128` and `U001..U128`), DURATION is `Envelope.decay` in ms (2..20000, 10 ms a click; the engine plays 0 or 1 as 1000 ms, so the page never offers them, and an old file that holds 0 shows 0 until the first click; RELEASE below 50 plays as 50), WARP X and Y are the two nibbles of `Lfo.wt_bend`, SUSTAIN is `Lfo.wt_sust` (new `ParamUnit::OffInt`: 0 reads OFF). A WT source reaches the voice only through the rebind (the live path stops at SOURCE >= 2.5 and the engine clamps a live source to 0..2), so a change is heard at the next note start or handover, not on a held note. After WT LFO back to LFO the contour byte stays in the file; the SHAPE row and the engine's read clamp it, so it shows and plays as Triangle. The contour picture was skipped for WT sources until W7b (it draws them now). QA rows: QA-INS-290..293 were already taken by OS-CEPLAYTHRU and the slicer, so W7a is QA-INS-294..299. AMOUNT (review fold): a non-amp WT Env takes its depth from `lfo[e].amount` (`put_mod`), and the amp slot's WT Env has none (voices law F7), so on slots 2..6 the last WT ENV row is `LfoAmount` (the WT LFO's row) and slot 1 shows seven rows without AMOUNT. - **W7b as built (2026-11-07, feat/OS-CEWTENV-W7b; new Community OS behaviour).** Slot 3 ("WT Position") is a bit mask in the enable byte: 0x01 is the wavetable position, 0x02 the granular length (the W5 destination). `model::wt_slot_follow_mode` (`model/src/params.cpp`) keeps the bit in step with the play mode (mode 7: 1 becomes 2; any other mode: 2 becomes 1; 0 stays 0). `Project::set_param` calls it after a SOURCE write of slot 3 or a PLAY MODE write, and `play_mode_set` calls it on the instrument it rewrites, so the mode change, the undo and the redo of either stay one unit and the bit agrees with the mode after every edit (the 1 to 2 and 2 to 1 flip on a mode change is new Community OS behaviour; the mask itself stays cited as F2). A loaded file is not rewritten: on a granular instrument the slot-3 SOURCE reader (`param_load`, so the dim rule and the rows below SOURCE too) counts the slot as on only when bit 0x02 is set, so a loaded enable of 1 (an OG file, an older project) reads Off, which is what W5 plays; on any other mode enable 1 or 2 counts as on. An OG export drops the granular grain length source (W5, by design). Test: `instrument_mod_test`, "a loaded granular instrument whose slot 3 enable is 1 reads SOURCE Off". The editor still writes 1 for a nonzero source (the model door converts it), `param_load` reads any nonzero enable as on, so a file written with bit 2 loads as before and an instrument that never uses slot 3 is unchanged (no format change: the byte already existed). The MOD page label for slot 3 reads "Gran Length" on a granular instrument and "WT Position" otherwise. The contour is drawn for the WT ENV and WT LFO sources: 64 points of `audio::wt_eval_shape(shape, phase, bend)` in one FT812 line strip through the existing `plot::draw_series` and the shared `params_curve_scratch()` (no new RAM). QA rows QA-INS-300..303 (the Gran Length slot, WT ENV and WT LFO contours with warps). The contour snaps are in `qa/qa_instrument_wt.txt` (with QA-INS-294..299 moved from `qa_instrument.txt`): the simulator binds the wavetable bank only after a `card` command and a run has one card, so a card-less run draws a flat line. ### 3.9 User contours (W8)

The main loop loads `/Envelopes/` after the card mounts and on a project load (F3 rules; through our WAV reader), resamples each file to 128 points, writes it to a spare buffer and swaps the slot's pointer with one aligned 32-bit store (the render reads the pointer once per evaluation). ### 3.10 CPU estimate [est] and what the unit measures

## 6. Assumptions (decided here; local, testable, reversible)

- A1. Contour indexes 0..127 are F001..F128 and 128..255 are U001..U128 (F1).
- A2. WT LFO uses our tempo-synced rate tables (29 rates, the amp's 24), which match tracker-ce's speeds (F6, F15).
- A3. An INST chunk older than the WT minor with loop 2 or 3 reads as loop 1: those bytes came from a tracker-ce file through an older build, which had already lost the contour and warps, and played them as an LFO.
- A4. The slot's RELEASE row is shown for WT ENV (tracker-ce uses the stored release but shows no row): new Community OS behaviour.
- A5. The granular length state lives in SDRAM (read once a block); the five SRAM `ModGen`s stay.
- A6. Live edits of the WT rows rebind the slot at the next quiet moment (as STEREO); a live ParamChange for them (OS-LFOLIVE style) is a follow-up.
- A7. y on an ADSR cutoff slot uses 8x / 8y ms (what the envelope receives in tracker-ce); the table values it also stores are not used (F10's open point).
- A8. The slot 3 enable byte's bits change meaning only for bytes other than 0 and 1, which only tracker-ce files carry; files of official 1.9 and of this OS read as before.
