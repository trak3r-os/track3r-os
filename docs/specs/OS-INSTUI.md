# OS-INSTUI — Instrument screen: navigation, types, delete, per-mode pages, MIDI

Status: specified 2026-10-14; S1 and S2 built, S2b (pad MIDI output), S3 and S4, S5, S6, S7, S8a (see the Built notes) · Absorbs OS-PLAYMODE (both parts) · Maintainer decisions 2026-10-14 · Classification: **new Community OS behaviour** unless a line says it is documented (the official manual or a release note) or Q (open research question).

## 0. What exists (verified 2026-10-14)

- **Params** (`app/src/screens/params_screen.cpp`, `params_screen.h`): F1 ENGINE (module picker), F2..F5 VOICE / FILTER / ENV / SENDS, F8 UNDO, Shift+F8 REDO (`bindings.cpp:534-546`). F6 and F7 are unbound. No Shift label row (Pattern has one: `soft_keys_shifted`). A pad selects instrument n (`bindings.cpp:537`); 48 pads, 64 slots: 49..64 only through the Instr-hold list (`bindings.cpp:539`). A right-hand card shows the descriptor (range, default, flags, CC). Header: `INS`, `KIND` (FREE / SAMPLE / MIDI / MODULE), `PAGE`.
- **Pads in the instrument editor**: this OS lets a pad sound a note of the instrument outside the pattern (D2); the instrument is chosen with Instr held. Whether the official firmware's instrument editor does the same is an open research question (Q): the repo holds no capture of it.
- **Play mode**: no screen shows or sets it except CHOP (sets beat slice). The wavetable and granular fields (`wavetable_window`, `wavetable_window_size`, `grain_length`, `grain_position`, `grain_shape`, `grain_type`) are stored (INST sampler block, `docs/formats/o3-project.md`) and played (`og_samples.cpp`) but nothing edits them.
- **Envelopes / LFO**: the engine plays each of the six destinations as an ADSR (enable, loop 0) or an LFO (enable, loop 1; shape, rate, amount from `lfo[slot]`) (`og_samples.cpp:250-272`, `voices.h:142`). The parameter tables have **no rows** for the loop byte or the LFO fields, so an OG project's LFOs play but cannot be seen or edited. All of these fields are already stored (INST sampler block offsets 44 and 164). The choices this spec lists: per destination Off / Envelope / LFO, LFO shapes Rev Saw / Saw / Triangle / Square / Random, 29 tempo-synced speeds (the official manual describes the six destinations, an envelope or an LFO or neither, five shapes and tempo-synced speeds, §6.5; not verified, see `docs/ui/official-manual-map.md`; whether the official firmware's labels are these is an open research question, the repo holds no capture).
- **Delete**: `Editor::clear_instrument` exists and is undoable (`editor.cpp:624`). The sample arena is a bump allocator (`sample_bank.h:14-16`): memory comes back at the next project load. The voices cannot unbind a module instance (`module_ui.h:19`). The sequencer ignores a step whose instrument slot is empty (`sequencer.cpp:1086`).
- **MIDI instruments**: only `midi_channel` is stored; no screen creates one. FX 37 is CC F in this build (`seq/fx.h:105` `kSlot37IsProgramChange = false`; what the official firmware sends for FX 37 is an open research question, OS-005 O1; decided in the S8a review: a saved FX 37 must not change meaning). Nothing but the channel is stored today. Documented in the release notes, not verified: six CCs A–F per MIDI instrument with selectable numbers incl. Program Change and aftertouch (PAR-042/043), CC-only steps (PAR-044), microtune as pitch bend (PAR-039/146), default velocity and an Offset (PAR-075).
- **Module parameters**: `o3m_param` is name / min / max / def / flags only (`o3module.h:129`); the pages are labelled "1-8", "9-16", ...
- **.pti**: reader and writer exist (`formats/builtin.h:92-96`, used by the OG folder import); Params does not use them. Documented in the release notes, not verified: 1.5.0 saves and imports single instruments (PAR-004).

## 1. Maintainer decisions (2026-10-14)

- **D1 Key row** (the pages move one place right; F1 is the source page):

  ```
  Normal: F1 <source>  F2 VOICE  F3 FILTER  F4 MOD    F5 SENDS  F6 <INS     F7 INS>     F8 UNDO
  Shift:  F1 NAME      F2 COPY   F3 PASTE   F4 DELETE F5 SAVE   F6 <USED    F7 USED>    F8 REDO
  Shift + Delete = INIT
  ```

  F1's label follows the instrument: SAMPLE / SLICE / WT / GRAIN for a sample instrument (by play mode), MIDI for a MIDI instrument; for a module F1..F5 are the module's pages (S10 names them). On an empty slot F1..F5 are the type chooser (D4). With OS-MODMX, F4 cycles MOD / MATRIX / GEN and its label carries the page (`MOD 1/3`).
- **D2 Pads play the instrument** on the Instrument screen (section 0; whether the official firmware does the same is Q). The instrument is chosen with F6/F7, Shift+F6/F7, the Instr-hold list, and Shift+pad (O3).
- **D3 F1 ENGINE is removed.** The type is chosen on the empty slot.
- **D4 Any slot can be any type; changing an assigned instrument's type = delete first** (maintainer, earlier the same day).
- **D5 Delete, simple version** (S5).
- **D6 MIDI**: a MIDI page, and Program Change reachable from the pattern: **decided in the S8a review: FX 37 stays CC F** (a saved FX 37 must not change meaning), and Program Change comes in S8b as a CC A-F slot set to PROG (the shape the release notes document for 1.3, PAR-042; not verified).
- **D7 Extras accepted**: `.pti` save/load, PASTE shares the sample, VEL> (velocity from an external keyboard; becomes a route of the modulation matrix if OS-MODMX M6 is accepted: `docs/specs/OS-MODMX.md`).
- **D8 INIT** on Shift + Delete (Delete resets one parameter; Shift + Delete resets the instrument).
- **D9 review accepted (maintainer, 2026-10-14)**: PASTE on a used slot **replaces** it (one undo unit, `INS 02 REPLACED · F8 UNDO`), refused only where a module instance is in the way (S5's module rule); the type chooser keeps D4 (empty slot only). The review's other changes are folded into O1, O7, O8, S1, S5, S6, S7, S8.

## 2. Orchestrator defaults (reversible, veto possible)

- **O1** F6/F7 step one slot (1..64), no wrap. Their labels show the neighbour (`<06`, `08>`) and are dimmed at the ends (no notification for a non-event). Shift+F6/F7 go to the previous / next slot in use, their Shift-row labels show those numbers; with none, the label is dimmed.
- **O2** Changing the instrument while a pad (or the preview) holds a note releases that note first, on the instrument that started it (no hanging note, MIDI out included).
- **O3** Shift+pad n selects instrument n without sounding (product-ux "Shift+pad: select without sounding"), so the old quick jump stays.
- **O4** The pads use the Pattern screen's current pad layout (OS-PADS-A, `pad_layer`); a beat slice instrument plays slice n on pad n (as Wave/CHOP). A MIDI instrument sends its notes to MIDI out on its channel.
- **O5** PLAY MODE and PLAY ENGINE live on the F1 source page (how the source plays); VOICE keeps level, pitch and colour, so no page passes `ParamView::kMaxRows` (8).
- **O6** The clipboard holds one instrument and is emptied by a project load (its sample lives in the arena, which a load clears).
- **O7** The type chooser only fills an **empty** slot (D4). PASTE replaces (D9).
- **O8** The right-hand descriptor card becomes a context visual (waveform with start / loop / end, the wavetable window, the grain window, the existing filter and envelope curves, a module's view); range, default and CC move to the footer line. Rows that do not apply are **dimmed, not hidden**, so every row keeps its place across play modes (all of FILTER when the filter is off; the MOD destinations the play mode does not use); only what can never apply to the kind is left out. One footer line names the keys acting on the row and, on a dimmed row, why (`FILTER OFF`). **Exception, the F1 source page**: its rows follow the play mode (PLAY MODE first, then that mode's rows, then PLAY ENGINE), so it never passes 8 rows (`docs/ui/ui-map.md` §3 item 7).
- **O10** The UI budget rules of `docs/ui/ui-map.md` §5 apply to every slice; a slice that changes the map updates it.
- **O9** All new stored fields (the S8b MIDI fields, and S9 VEL> unless OS-MODMX M6 turns it into a route) go in **one** INST minor-version bump (1.3).

### S1 — Navigation, key rows, header
- Params soft keys per D1 (`kParamsSoftKeys` and a new `soft_keys_shifted` table); F6/F7 and Shift+F6/F7 per O1 (new actions, bound in the Instrument context). Labels at most 7 characters; state goes in the header, not in the label. F1 ENGINE's binding goes (D3); the module picker stays reachable from S5's chooser. Until S5 lands, F1 keeps opening the picker on an empty slot so a module can still be bound.
- The Params button no longer cycles the pages (UI map rule 3, no cycle inside a cycle, once F4 cycles with OS-MODMX): pressed again it goes to F1. Every Shift+F binding of the screen is on its Shift label row, and a binding test fails a Shift binding without a label (UI map rule 3).
- **Left / Right = previous / next page, wrapping** (maintainer, 2026-10-14; the rule "on a paged screen with a single column, Left/Right change the page", as in Config and Record through OS-SHIFTROW). Exception: on a module instrument with kits, Left/Right select the kit (UI map rule 2), and the page stays on F1–F5.
- Header: `07 NAME · SAMPLE · ONE SHOT · MODERN` (kind, play mode, play engine; read-only in S1). Module: `· TB303`; MIDI: `· CH 3`.
- Acceptance: host tests for O1 (ends, skipping empty slots, an empty project); the binding table and the generated key reference updated; sim goldens for both key rows and the header.
- **Built**: `ParamsScreen` key row via `params_key_row` (F1 follows the kind: SAMPLE / SLICE / WT / GRAIN, MIDI, a module's `1-8` … `25-32` (or its page names) for the pages it has and blank beyond them (OS-MODPAGEKEYS; a module with no parameters: no key at all, the info line says `NO PARAMETERS`), MODULE on a free slot; F6 / F7 `<06` / `08>` dim at the ends; Shift row NAME / COPY / PASTE / DELETE / SAVE, `<NN` / `NN>`, REDO), actions `instrument.page` (F1..F5), `instrument.step` (F6 / F7), `instrument.used` (Shift + F6 / F7), `instrument.later` (Shift + F1..F5), `Screen::repress` (the Params button again → page 0). Header `07 NAME  SAMPLE / ONE SHOT / AUTO>AMIGA` (the kind, the play mode and the engine, no PAGE field: the page is the right-hand header; Auto shown as `AUTO>AMIGA`, resolved by `SampleBank::engine_for`; `AUTO` alone where there is no bank) and `MIDI / CH n` for MIDI. Deviations and decisions: (1) **inert until their slice**: F1 on a sample / MIDI instrument (the source page, S3 / S8a) and Shift + F1..F5 (NAME and the rest, S5 / S7) show their D1 labels **dimmed** and, pressed, post `... : OS-INSTUI Sn` (a placeholder binding keeps the shift-label test honest); (2) the **ENV page keeps its second axis**: Left / Right walk the six envelopes first and turn the page past either end (arriving from the left lands on envelope 1, from the right on 6), so the arrows never trap you on it; (3) **no kits exist** in the module ABI, so Left / Right turn the pages of a module too (the kit exception arrives with the drum-synth module); (4) a module's F1..F4 are its pages (`kModuleMax` 32 is four pages; F5 is unused until S10 allows five); (5) the Params button goes to the first page that exists (a module's first, else VOICE) until S3 builds the source page; (6) the group name of the F4 page is still `ENV` in the header (S6 renames it MOD).

### S2 — Pads play the instrument
- Instrument context: pad tap → the live-note path the Wave screen uses (`PreviewSink::pad_down / pad_up`, `audio/live_notes.h`), note from the current pad layout (O4); Shift+pad → `instrument.select` (O3); O2 on every change of instrument. Pad LEDs as on Pattern for the layout.
- Acceptance: host tests (note mapping per layout, slice mapping, release on F6/F7); qemu or sim scenario: a pad sounds the instrument in view; HW check: no hanging note with a MIDI instrument.
- **Built**: action `instrument.pad` (Instrument context, all 48 pads) → `PreviewSink::pad_down` with the layout's note (NOTES board; PIANO / ISO as on Pattern, their jump and octave pads dead; a beat slice instrument 24 + n; the other layers' pads play the NOTES board); Shift + pad → `instrument.select`; `ViewState::inst_pads` remembers the pads this screen started and `release_live_pads` ends them (`PreviewSink::pad_up`, which the sink resolves to the instrument that started the note) on F6 / F7, Shift + F6 / F7, `instrument.select` and the Instr-hold list (O2). `ParamsScreen::pad_roles`: PIANO / ISO draw their keys (note pads only), NOTES leaves the LEDs to the held-pad policy, as Pattern. **MIDI output is not built**: no live path from the main loop to the MIDI emitter exists (only the sequencer's events reach `MidiOut`, and `MidiOut` has one producer, the render), so a pad on a MIDI instrument reaches the sink and sounds nothing; O2 holds by the sink's contract (the pad's release ends whatever the pad started). **S8a must re-verify O2 "MIDI out included" against a real sink: it is untested here (the host sink is a log).** The live MIDI note-on / off on the instrument's channel is S8a's (its test line already says "a pad on a MIDI instrument emits note on/off on its channel"); it needs a main-loop to render queue for MIDI events (Level C: real-time path): built in S2b below.

- **S2b Built** (Level C, real-time path; **new Community OS behaviour**): a pad on a MIDI instrument sends MIDI. **One queue, no new ring**: the pad's note-on and release travel the existing live queue (`LiveQueue`, main loop the one producer, the render the one consumer, `audio/live_notes.h` QUEUE CONTRACT unchanged). `Engine::play_live` offers every event it pops to `EventSource::live` (a new optional hook, null for every other source) before it acts; `seq::MidiLink::live_event` (render context) answers true for a **pad** note-on whose instrument is of kind Midi, and the engine then starts no voice and takes no track. The note becomes a `MidiNoteOn` through `MidiOut::send`, so the router's rules (DIN/USB queues and running status, OUT OFFSET, the hang book, suppress, panic) hold unchanged. Channel = `midi_channel - 1` (the sequencer's rule), velocity 127 for the pad's default (as a step's), an explicit 1..127 otherwise. **Release never looks at the instrument**: `MidiLink` keeps `live_pad_[48]` (render only, one word a pad: held bit, channel, note, 96 bytes of SRAM_U) and a pad's `Off` (or an `AllOff` of the pads or of all sources, `App::reset_input`) sends the note-off for what was stored at the note-on. So a change of instrument (F6/F7, Shift+F6/F7, the Instr-hold list, Shift+pad: S2's `release_live_pads` pushes the Off first), a project load, a changed channel or kind, and leaving the screen cannot leave a note on; a pad that goes down while it holds a note ends that note first. **Ordering**: `play_live` runs after `MidiLink::step` of the block (whose flush has gone), so a live note is stamped at the first sample of the **next** block (`last_block_end_`, offset 0): behind every sequencer event of the block it was popped in, ahead of every one of the next block's (`TimedQueue` is a stable sort, equal due times keep staging order), so each port's ring stays in due order; it is one block (1.45 ms) later than a sample voice, which starts at sample 0 of the block it is popped in. **Overflow**: the live queue is 64 events and the render takes `kLivePerBlock` (16) a block, the rest waits in order; a full queue refuses the producer, which counts it and for a lost Off/AllOff sets `flush_`, so the next call sends an all-notes-off (`LivePreview::tick`); the table cannot overflow (indexed by pad); the router's staging queue (256) is bounded by the live path to at most 32 entries a block and a note-on it refuses is not owed an off (`MidiOut::send`). **Stop / panic**: a Stopped event's `stop_all` takes live notes with the rest (a staged note-on is dropped, a sounding one gets its off behind the horizon); the pad's later Off is then not owed and is dropped (`stray_offs`). Not in this slice: the MIDI keyboard and the preview sources do not drive MIDI instruments (they keep their pre-S2b behaviour: no MIDI; S8a scope), a muted track does not silence a pad's note (the pad has no track on the MIDI side), and a pad's own velocity does not exist yet (127). Cost: mk66 `.text` +352 B, `.ramfunc_l` +76 B (the hook call in `play_live`; 27,076 of 27,648), `.bss` +96 B (SRAM_U). Known limits (review APPROVE WITH MINORS): the hang book is shared with the sequencer per channel and note (a sequencer off cuts a held pad note and the reverse; one receiver voice per note is assumed); a pad pressed in the few blocks after a Stop can be taken by the panic pump; a pad off refused by MidiOut's staging (driver fault) is not resent, so that note hangs until the next Stop or panic. S8a must re-verify O2 against a real receiver. Tests: `audio_live_midi_test.cpp` (render level: pairs on channels 1 and 16, velocity, sources, hang rules, stop, queue bounds, ordering against the sequencer's MIDI), `inst_live_midi_test.cpp` (the app's pads through every change path, a load, a lost input, Stop), `support/live_midi_rig.h`. QA-INS-033 / 034; HIL `qa_instrument.json`.

### S3 — F1 source page and play mode
- New descriptor rows, **appended** to `instrument_param` (existing ids keep their numbers; the generation block grows: report the SRAM delta): PLAY MODE (8 labels: ONE SHOT, LOOP FWD, LOOP BWD, PING-PONG, SLICE, BEAT SLICE, WAVETABLE, GRANULAR; OG order `play_mode` 0..7), and per mode: WT POS and WT SIZE (wavetable), GRAIN POS / LENGTH / SHAPE / LOOP (granular), SLICES and SLICE (slice modes). PLAY ENGINE moves to this page (O5). No format change: every field is stored already.
- PLAY MODE edits go through a validating action (as PLAY ENGINE's): SLICE / BEAT SLICE with no slices offers AUTO / EVEN on Wave; WAVETABLE needs a valid window size (this OS's default-window rule); refused changes say why.
- O8 context visual and dimmed rows.
- Acceptance: param tests (defaults equal `init_instrument`, ranges as this OS's table lists them), action tests for the validation, goldens for each F1 variant.
- **Built**: **model**: nine rows appended at ids `0x14..0x1C` (`instrument_param::PlayMode.. Slice`, `kSourceFirst`; not at 14: 0x10..0x13 are the audio side's live ids) and the group `GroupSource` = 4 (the key order is SOURCE, VOICE, FILTER, ENV, SENDS; `kKeyOrder` in `params_screen.cpp`); PLAY ENGINE moved to the source group (O5, id 13 unchanged); `kCount` 50 -> 59, so the generation block grows by 64 x 9 x 4 = **2,304 B** (it lives in the model arena in SDRAM: `kModelArenaBytes` 1,920,144 -> 1,922,448, mirrored in the mk66 map and README; the SRAM delta is in the mk66 numbers of the commit). Ranges and labels are this OS's choice (the test lists them). WT SIZE and GRAIN LENGTH read 0 = "not set" (init_instrument keeps zeroing them: the persist2 test pins the writer's bytes), shown and stepped as 2048 / 441; `og_samples.cpp` plays a grain under 44 as 441. WT POS, GRAIN POS / LENGTH / SHAPE / LOOP and SLICE are learnable; PLAY MODE, WT SIZE and SLICES (a readout: the slices are made on Wave) are made by their actions and are not. **actions**: `play_mode_set` / `instrument.play_mode` (arg 0..7, -1 / -2 previous / next) with this OS's rules (the window fitted to the length, the sample type, the grain kept a grain, a broken loop given the whole window; WAVETABLE on a sample under 32 frames refused with the reason; SLICE / BEAT SLICE with no slices allowed and says AUTO OR EVEN ON WAVE); `write_param` routes the source rows through `source_param` (clamps to the sample: position to the windows there are, grain to 44.. min(length, 44100); WT SIZE by counters with the position moving, `wave_math.h wt_*`); an edit rebinds the slot (nothing goes to the engine's table; the two positions are also live `WtWindow` / `GranPos` changes of a sounding voice). **screen**: F1 opens the page; the rows follow the mode (PLAY MODE, the mode's rows, PLAY ENGINE: at most six); O8's context visual (the sample with START / END, the loop, the slice lines, the window or the grain marked) replaces the descriptor card on this page, with the range and default on the info line, which also gives the reason a dimmed row does not apply. Deviations: (1) **the descriptor card stays on the other pages** (the context visuals of O8 for VOICE / FILTER / ENV / MOD are not part of S3); (2) the header's "n/N" counts in key order (SOURCE 1/5; a free slot or MIDI instrument has VOICE 1/4); (3) a MIDI instrument's F1 stays a placeholder ("MIDI PAGE: NOT AVAILABLE YET") until S8a. The review fold of S1 / S2 is its own commit. **S3 / S4 review fold**, commit `fix(app): OS-INSTUI S3/S4 review fold`): (1) WT POS and SLICE are **not learnable until a CC scale onto the window / slice count exists** (they clamp to the windows / slices there are, so a CC over 0..65535 landed on the last one for every value above 0); (2) `make_sample_desc` fits an unset or invalid WT SIZE (0) to the sample with `wt_fit_size`, as the page shows it (an unset size on a sample under 2048 frames played silence; a stored valid size the sample cannot hold still plays nothing, this OS's rule, OS-007h); (3) the 450 ms repeat-vs-fresh rule of `instrument.turn` (`kTurnFreshMs`): a deliberate second press within 450 ms that would wrap is dropped (it is taken for an auto-repeat); (4) `play_mode_set` is **new Community OS behaviour**: the loop repair uses the whole play window, the grain clamp and the refusal under 32 frames are the OS's own, and a playing note keeps the old mode until the rebind (what the official firmware does at a mode change, repair and playing notes included, is an open research question).

### S5 — Type chooser, DELETE, INIT
- **Empty slot**: the page shows the chooser: F1 SAMPLE (Sample Load with this slot as target, back to Params after the load), F2 MIDI (creates a MIDI instrument on channel 1, opens the MIDI page), F3 PASTE (S7; the key of Shift+F3), F4 MODULE (the existing module picker, `ModuleUi::pick`), F5 LOAD (S7; the key of Shift+F5 SAVE).
- **DELETE** (Shift+F4): `Editor::clear_instrument`, one undo unit, no dialog; notification `INS 07 DELETED · F8 UNDO`. Steps are not touched (they stay silent; a new instrument in the slot plays them). Nothing on the card is touched. The sample's slot in the bank is made silent at the next quiet handover; its memory comes back at the next project load. A module slot: the instance stays bound (no unbind exists), so that slot refuses a new **module** until the project is reloaded ("RELOAD TO PUT A MODULE HERE"); a sample or MIDI instrument is allowed — **the engineer verifies that the old instance never sounds** for a slot whose kind is no longer Module, and adds a test. Undo restores the instrument (the PCM is still in the arena; the instance is still bound).
- **INIT** (Shift + Delete): every parameter of the instrument back to its descriptor default (a module: its blob back to the module's defaults), kind, sample, module and name kept; one undo unit, no dialog.
- Acceptance: editor and action tests (delete / undo / redo, INIT keeps the source, PASTE replace and its module refusal (D9)), the module-slot test above, goldens for the chooser.

### S10 — Module ABI minor (page names, enum labels)
- Additive, one minor bump of `O3M_ABI_MINOR`. **1.3 is taken by ADR 0014 slice H1 (capabilities, host tables), which merges first (amendment D); ABI minors are claimed in merge order, so S10 takes the next free one when it merges (1.4 if it is next; **1.4 is claimed by ADR 0014 slice H2a, the audio tap, when that merges first, and then S10 takes 1.5**).** It adds an optional page table (name + first parameter) and optional value labels for INT parameters.
