# Module app: feature catalogue

One row per user-visible function of the common page of a module app (`docs/ui/ui-map.md` section 1, the Module app row; fixed table of `docs/specs/OS-FINALQA.md` section 1). IDs are never reused. The simulator scenario is `sim/scenarios/qa/qa_module_app.txt` (the card of the shipped apps: `card e2e_card`, `apps on`, MODULES `F1`, MIDI Monitor as the page), its goldens are the `qa_module_app/qa_app_NNN` keys of `sim/goldens.txt`.

What is common to every app page is here; what one app does is in `modules.md`. Already catalogued there and not repeated: the key labels an app declares and the Shift row (QA-MOD-120, `qa_mod_120`, `qa_mod_120_shift`), F8 BACK and the F7 + F8 chord (QA-MOD-121, `qa_mod_121_f8`, `qa_mod_121_chord`), the legacy row of an app of ABI 1.2-1.8 (QA-MOD-122, `qa_mod_122`), the grammar of an app's own rows (QA-MOD-123), the Shift layer by ABI (QA-MOD-125) and the screen buttons (QA-MOD-128). The rows below add the pictures those rows lack and the keys they leave out.

The OS's parameter column (a `PARAMETERS` header and a row per declared parameter on the left) exists only for an app built below ABI 1.10 that declares a parameter; an app of ABI 1.10 draws its own rows and gets every key. The only such app is Pads, the SDK example: it has no manifest, so it is not on the simulator's card and QA-APP-005..007 have no picture; they are host-tested.
