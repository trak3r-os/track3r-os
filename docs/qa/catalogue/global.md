# QA catalogue: Global

Screen: none. Global keys, transport, MIDI, USB, storage and the diagnostic console (`diag`), the functions that belong to no one screen. Table format: `docs/specs/OS-FINALQA.md` section 1. This file holds the rows added by the items that touched them since the rule of section 2; the rest is drafted in the final batch (section 3).

Sim scenarios would be `sim/scenarios/qa/global.txt`; unit scenarios are `platform/mk66/tools/hil/qa_global.json`, whose command steps are named by the row id their `note` begins with (`QA-GLB-003: ...`: the Unit column below gives that name; one step for one row). The simulator has no cycle counter and no console, so the CPU rows have no simulator column: their arithmetic is proved on the host (`tests/module_governor_test.cpp`, `module_perf_thread_test.cpp`), the cycles only on the unit.

## Module instruments' CPU measure (OS-303PERF)

`diag mod` lists, for each module instance, where its state and its hot code run from and, while the measure is on, a second line with what the render measured of it: the whole instance loop, the module's `render()` alone, the output side (zero-fill and Q15 conversion) and the hooks (enter, leave). `diag cpu reset` turns the measure on (it is off from boot, so a normal session pays one flag read; every scenario that starts with `cpu reset` leaves it on) and starts its figures again together with the engine's maxima; `diag cpu perf off` turns it off. While it is on, the governor's own figure (`cycles/voice`, the render time in `diag cpu`) carries about three counter reads a segment more than with it off, so a baseline is taken with it off. `diag bench tb303` and `tb303_128` time `render()` alone on a private instance at 64 and 128 frames. A figure is a number of cycles of the 180 MHz counter; a sample is one full block of the instance. The qa_global scenario captures the readings into the log (step key `show`); it does not judge them. For the figures without USB traffic the unit should present STANDARD (Config > USB, USB AUDIO Off, F7 twice, by hand: the console goes with the re-enumeration); the scenario checks it softly and the report says which mode the figures were taken in. A held note is measured for 8 s (it sounds about 17 s), a song for 60 s.

## The SD card taken out and put back (OS-SDSWAP)

The card used to be mounted once, at boot: after a swap every read failed with an i/o error until a reset. Now the unit follows the card-detect pin (a level has to hold 250 ms), lets the volume go when the card leaves and mounts the card that comes in, by itself. Strip texts: `CARD REMOVED`, `READING CARD`, `CARD READY`, `CARD NOT READABLE` (the HIL `state` line prints them as `msg=CARD_REMOVED`, ...). The unit scenario `qa_sdswap.json` needs a person to pull and put back the card (its `say` steps tell when; the steps after poll up to 90 s) and writes nothing; `qa_sdswap_save.json` needs the test card and writes a project folder. The simulator has no card slot, so there is no simulator column. The logic is proved on the host (`platform/mk66/tests/mk66_storage_swap_test.cpp`, on QEMU too; `tests/file_screen_test.cpp` for the strip and the rescan).

## The Power switch (OS-POWER, slices P1 and P2)

`docs/specs/OS-POWER.md`. The rear Power switch (PTC3) is a platform input, not an `app::Button`: holding it for 2 s switches the unit off (the stages of the shutdown, USB off, the lights out, then, after Power is released, **slice 2: the VLPR off**: the chip in very-low-power RUN with the pins quiet and the SDRAM's supply removed, PTC3 polled, a press boots the unit; `diag power off dry` and a build with `-DO3OS_POWER_VLPR_OFF=OFF` end in P1's restart instead). A line across the top edge shows the hold, the strip says what is happening. Everything here is new Community OS behaviour, no parity is claimed. Sim scenario `sim/scenarios/qa/qa_global.txt` (snaps `qa_glb_NNN`, goldens `qa_global/qa_glb_NNN`; the platform's stages are not simulated, their proof is `platform/mk66/tests/mk66_power_service_test.cpp`); unit scenario `platform/mk66/tools/hil/qa_power.json` (injected: `diag power press|release`; the physical switch rows are manual). **The first unit run is `diag power`, then `diag power off dry`, with no button held** (QA-GLB-113); then `diag power off`, also with no button held, then the wake rows (QA-GLB-103, 117). Ids 100..117 are reserved for this item.
