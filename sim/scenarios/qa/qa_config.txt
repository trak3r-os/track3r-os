# OS-FINALQA (docs/specs/OS-FINALQA.md): the Config screen's QA rows, docs/qa/catalogue/config.md. One `snap qa_cfg_NNN` per row with a visible result; the goldens are keyed config/qa_cfg_NNN.
# OS-USBAUDIO: Config > USB (F5). USB AUDIO and USB RETURN are press to apply: the encoder (or Delete) only changes a pending value (starred), F7 says what will happen and arms, the second F7 writes
# the settings; RETURN LEVEL is live. The message says a reconnection only when the apply re-enumerates the USB port: a USB AUDIO change always, a USB RETURN change only while AUDIO is presented.

# QA-CFG-001: the USB page (F5): USB AUDIO On, USB RETURN On, RETURN LEVEL 100, nothing pending.
tap config
tap f5
snap qa_cfg_001

# QA-CFG-002: USB AUDIO to Off by a turn: the row is Off and starred, the info line says it is not applied yet. Nothing is written.
encoder -1
snap qa_cfg_002

# QA-CFG-003: the first F7: "USB WILL RECONNECT: PRESS AGAIN" (the mode changes), the info line asks for F7 again. Still nothing written.
tap f7
snap qa_cfg_003

# QA-CFG-004: the second F7 writes it: Off with no star, "USB RECONNECTING". (A notification shows for 2 s and the next one waits behind it: the scenario waits the first out after the press, as params.txt does. The press comes while the question is up: a later one would ask again, OS-BUG-CFGARM.)
tap f7
wait 2500
snap qa_cfg_004
wait 2500

# QA-CFG-005: STANDARD now. USB RETURN to Off on the next row: starred, pending.
tap down
encoder -1
snap qa_cfg_005

# QA-CFG-006: the first F7 for a lone USB RETURN change in STANDARD: no reconnect warning ("PRESS AGAIN TO APPLY"), STANDARD's descriptors do not depend on the return.
tap f7
snap qa_cfg_006

# QA-CFG-007: the second F7: "APPLIED", USB RETURN Off, no star, no "USB RECONNECTING".
tap f7
wait 2500
snap qa_cfg_007
wait 2500

# QA-CFG-008: RETURN LEVEL is live: -10 detents is 90 at once, no star, no APPLY.
tap down
encoder -10
snap qa_cfg_008

# QA-CFG-009: Delete on a press-to-apply row is the default as a pending value: USB AUDIO is Off, so On waits (starred).
